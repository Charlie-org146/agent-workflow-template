# Start here

Generated by `entry.py write` from this repo's PRD pages and `.loop/config.json`. Don't edit it by hand: change a page or a setting, then run `docs.py audit`.

## First five minutes

1. Read this page: how the parts fit together, every feature and how to use it, and every setting.
2. Ask for `workflow-monitoring report` to see what is running and what waits on you.
3. Start a goal by asking for `workflow-monitoring go "goal" --done "line"`.
4. Each skill's Command map, in its SKILL.md, names the exact script behind every ask.
5. Run `entry.py lag`; if it prints a line, this repo is behind the template: tell the owner.

## Loop

A goal is one sentence with frozen done lines. A worker takes it through idea, plan, build, review, qa, ship, pull request and release, on branch `loop/<slug>` cut from `main`. Each step's skill is chosen in the private flow file, `~/.workflow-loop/flow.json` (`built-in` runs delivery's own routine). Review is the only gate. Plan and review run at `full` depth; auto-approval is `true`; a goal stops after 3 failed tries; its token budget is 3000000 (0 means none).

## Release

Release is a goal's last step: it brings the docs up to date, bumps `VERSION` and writes the release note. Auto-merge is `true`; a pull request bumps the version itself: `false`. Your own routines after a release: none.

## Operation and workers

One session governs and the others build: the operation session assigns goals, watches them and answers what waits on you, and never builds. Up to 0 workers run at once (0 means no limit). It checks in every 30 minutes; mending a failed goal is `true`, resuming after a usage limit is `false`, and watch looks again every 20 seconds.

## Docs

Feature pages live in `docs/wiki`, one PRD page per feature with numbered requirements, at most 24 each. The criteria contract is `true`. The docs command finds stale pages, and the release step rewrites them.

## Regression

Every requirement and every fixed defect has a regression row in `.loop/regression.tsv`, seen failing before its fix. The land lane runs once per goal, in qa, within 15 minutes (the budget; rows past it are left to the scheduled run), after at most 25 minutes of preparing, planning and waiting for a slot before its first row; the scheduled run is `17 */4 * * *`.

## Health

Health checks the repo with fixed rules that give the same answer every time, on the schedule `47 */4 * * *`; a branch or worktree older than 14 days is stale. The judge runs on the Mac with your own claude login.

## Settings

Every repo setting, its value and its one-line explanation is in the Settings table below; add any missing one with `/workflow-setup fill-repo`. Private settings live in `~/.workflow-loop/` and never appear here. The wiki Home page also carries a Settings section (each setting's meaning, how to set it, its default and this repo's value, marked overridden) and an Automation section (each routine on or off, its cadence, where it runs, its last run and any step you still owe); the README repeats both and names the template repo it came from. `/workflow-docs render` refreshes them.
