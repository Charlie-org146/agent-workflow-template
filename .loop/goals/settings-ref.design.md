# Design: settings-ref

Problem: `skills/workflow-setup/references/settings.md` is generated by `settings.py reference --write`, but the committed file has drifted from `settings.py`: it lacks `review_hold`, `eta_margin_percent`, `max_regression_rows` and `max_suite_seconds`, and carries older wording for others (auto_merge reads "and publishes its release" where the table says "and publish"). `entry.py` builds START.md's settings part from that file, so START.md shows the old text (#4539).

Approaches:
1. Regenerate the reference and START.md once. Cost: tiny; risk: it drifts again.
2. Regenerate, and add a row that compares the committed file with `settings.py reference` output and fails on any difference. Cost: one row and no growth in settings.py (cap 19,133 bytes).

Chosen: 2. Done line 1: `settings.py reference --write` then `entry.py write`; START.md then holds today's auto_merge and review_hold lines. Done line 2: a row `settings-reference-fresh` (diff of the committed file against the generated text), seen red on the old file.

Open questions: none.
