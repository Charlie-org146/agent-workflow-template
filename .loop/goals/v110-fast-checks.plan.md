## What is built

1. `skills/workflow-delivery/scripts/quick.py` (moved from `dev/`, so it ships to adopted repos and sits inside the declared Touches). ONE command, `quick.py run`, runs the three checks in one process on one clock and prints `QUICK ok (<s>s)` or `REFUSED: <check> failed: <what>. Fix: <command>`; the limit is DEL-25.2's single 1 minute, or the `quick checks` name of `clock.limit` once v110-fast-clock is on main (the run prints which it used). The three checks: `lint` (compile the changed `.py` files in memory, `bash -n` on changed `.sh`); `docs-check` (`docs.py check` and `entry.py check`); `size-limits` (`package.py --static` plus a diff against 19,000). "Changed" means `git merge-base HEAD origin/main` to HEAD, never the push's refs; a new branch and a push of several refs check the same files; with no `origin/main` every tracked file is checked. There is no ppid stamp and no per-hook fallback.
2. `.pre-commit-config.yaml`: one local hook `quick`, `language: system`, `entry: python3 skills/workflow-delivery/scripts/quick.py run`, `pass_filenames: false`, `always_run: true`, stage pre-push. `language: system` builds no virtual environment, so no setup time counts against the 1 minute. The file is written into a repo by `quick.py install` when it is absent.
3. Installing the hook (so a push really runs the checks): `quick.py install` runs `pre-commit install -t pre-push` where `pre-commit` is on PATH and prints the ordered Fix where it is not. `seed.py` (already in Touches via `skills/workflow-setup`) learns that a pre-commit shim whose `pre-push.legacy` is the loop's own stub is ours: `hook_state` reports it as installed and `git_hooks` and its `--check` count it good, so `setup.py --git-hooks` neither reports it foreign nor reinstalls over it. `setup.py` is not edited. The toy covers: stub alone, stub plus shim, and a foreign hook. The quick checks run through pre-commit on macOS and Linux; `quick.py run` is the by-hand route elsewhere.
4. The lane skip (DEL-25.3; owner ruling o830; granted TD1135), BUILT: `skills/workflow-delivery/scripts/skip.py` (new, shipped with the skills). `lane(base, head, name)` returns `("skipped", SKIPPED line, [])` when GitHub runs this repo's tests; otherwise the lane runs and says why (the conditions are in the code and pinned by the toy). A skipped lane is NEVER a pass and writes NO `.ok`: `.last` records state `skipped` (not terminal), `<step>-lane.txt` starts with the SKIPPED line, and `<step>-lane.skip` holds the head. `lane-wait` exits 3 for it; the PR body prints the SKIPPED line. `accepts(runs, slug, step, head)` is the reader `lanekit.lane_ok` calls, so record qa and ship accept a recorded skip only when GitHub's checks on that exact head are acceptable. `lane.py` calls `skip.lane` after the stale-job stops and the `.last` reuse; `goal.py pr` passes `gate == "pass" or None` to `private.pr_result`, which posts no status for a skipped lane. The exact rules are pinned by `test-local-lane.py`.
4a. BUILT: `skills/workflow-delivery/scripts/regen.py` (new, shipped with the skills): `check(g, slug)` and `regen(g, slug)`. At `goal.py pr` the generated files (START.md, wiki pages) are CHECKED and never rewritten. A stale file prints `NOTE: REGEN_STALE: <files>` with the ordered Fix (`entry.py write`, `wiki.py prepare SLUG --commit`, commit, re-run the lane, then `goal.py pr`); a REWRITE page is named as needing an agent. `fit.regen` is `import regen as made; return made.regen(g, slug)`, so it applies to adopted repos too and the old rewrite-and-commit body is gone. In v1.1.0 this is a note; the hard stop ships in v1.2.0 after #5728 and #5783.
5. Who writes generated files now (the lane no longer does for a skipped goal): the writers are the existing commands, named in the Fix line and run by the worker at ship: `entry.py write`, `wiki.py prepare SLUG --commit`, and the Tests-table render that `lanekit.prep` runs today. The `docs-check` quick check refuses a stale page at push, before the PR, so the worker finds out at the push and not at the pull request; pages stale only by commits since their stamp are restamped by `wiki.py prepare SLUG --commit` (DOC-2). The earlier claim that the lane restamps them is withdrawn. `REGEN_STALE` is a note at `goal.py pr` in v1.1.0 and becomes a hard stop in v1.2.0 after #5728 and #5783.
6. Version bump: `goal.py pr` keeps today's order (the regen check, then the bump). With `pr_bumps_version` on (default false) the bump is the one commit `pr` can make and DEL-25.4's "head unchanged" does not hold for that setting; the PR notes say so and the toy asserts the default. If top wants the bump to refuse instead of commit, that is a small separate change.
