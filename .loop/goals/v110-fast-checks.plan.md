# Plan: v110-fast-checks (DEL-25), revised after gate 5 (TD1043, TD1105, TD1106, TD944)

This text replaces every earlier revision; the design file `.loop/goals/v110-fast-checks.design.md` is rewritten to match it. It plans against DEL-25 as pinned by the owner (o740: no full test lane runs on the machine; a machine runs a lane only when GitHub is unavailable) and the limits of o755 (quick checks 1 minute, DEL-25.2). This goal never marks DEL-25 reviewed. Nothing is built, pushed as code or run as a lane until the gate is clean and the operation says so.

## Rulings that stand

1. No GitHub status and no `.ok` is ever written for a skipped lane. `.ok` means a tested pass and nothing else.
2. No comment or docstring trimming to fit a file (GRD-20). The frozen done line 3 ("none newly crosses 19,000") beats the warn band of TD1028: a touched script that is under 19,000 stays under it; a script already over 19,000 on main may grow but never past 20,480, and a file that would pass 20,480 gets ONE whole helper moved, unchanged, into an existing script with room.
3. `role.py`, `merge.py`, `guards.py` and `replan.py` stay byte-identical to main.
4. The quick checks run through the pre-commit framework; the git-native private-name stub stays as pre-commit's `pre-push.legacy` hook (TD839) and is not changed. The PR notes say plainly that this is a gap in the letter of done line 2 and give the reason in one sentence; the owner decides whether it needs a new goal.
5. Order: fast-text-2 merges first (about 15:25), then this goal merges main up, re-measures bytes and re-keys its row to DEL-25.
6. DEL-17 and DEL-25.3 (TD1111 point 4). DEL-17 (Reviewed, Delivery.md line 47 on main): "then one local lane (5 minutes, only the tests the change reaches, reused by later steps)". DEL-25.3 (fast-text-2, Delivery.md line 123): "No full test lane runs on the machine. Tests run on GitHub (DEL-26). A machine runs a lane only when GitHub is unavailable." Read together they do NOT conflict for the quick checks (DEL-25.1 and .2 add checks before a push and take away no lane) and the build follows both there. They DO conflict, as written, on whether the machine runs the test lane: the lane DEL-17 describes is the test lane DEL-25.3 takes away. That one part (items 4 and its toy: the lane skip) therefore HOLDS FOR THE OWNER; this goal builds no skip before the owner or top rules, and DEL-17's text is not edited here (DOC-2). Everything else (quick.py, the hook, install, the generated-file check, the rows) does not depend on it.
7. How the gating run happens: a full-suite GitHub run at the pushed head (TD1106: one at a time, Fast first, `ready-to-dispatch <sha>` to the operation and the Mac's go; this worker never dispatches by itself), plus the Mac subset the operation names, run in a fresh clone with a temporary HOME. After any run the worker comments on and fixes every issue that run opened or closed from branch-only results.

## What is built

1. `skills/workflow-delivery/scripts/quick.py` (moved from `dev/`, so it ships to adopted repos and sits inside the declared Touches). ONE command, `quick.py run`, runs the three checks in one process on one clock and prints `QUICK ok (<s>s)` or `REFUSED: <check> failed: <what>. Fix: <command>`; the limit is DEL-25.2's single 1 minute, or the `quick checks` name of `clock.limit` once v110-fast-clock is on main (the run prints which it used). The three checks: `lint` (compile the changed `.py` files in memory, `bash -n` on changed `.sh`); `docs-check` (`docs.py check` and `entry.py check`); `size-limits` (`package.py --static` plus a diff against 19,000). "Changed" means `git merge-base HEAD origin/main` to HEAD, never the push's refs; a new branch and a push of several refs check the same files; with no `origin/main` every tracked file is checked. There is no ppid stamp and no per-hook fallback.
2. `.pre-commit-config.yaml`: one local hook `quick`, `language: system`, `entry: python3 skills/workflow-delivery/scripts/quick.py run`, `pass_filenames: false`, `always_run: true`, stage pre-push. `language: system` builds no virtual environment, so no setup time counts against the 1 minute. The file is written into a repo by `quick.py install` when it is absent.
3. Installing the hook (so a push really runs the checks): `quick.py install` runs `pre-commit install -t pre-push` where `pre-commit` is on PATH and prints the ordered Fix where it is not. `seed.py` (already in Touches via `skills/workflow-setup`) learns that a pre-commit shim whose `pre-push.legacy` is the loop's own stub is ours: `hook_state` reports it as installed and `git_hooks` and its `--check` count it good, so `setup.py --git-hooks` neither reports it foreign nor reinstalls over it. `setup.py` is not edited. The toy covers: stub alone, stub plus shim, and a foreign hook. Native Windows keeps the stub alone and never installs pre-commit; `quick.py` says so in one line, and the PR notes list this platform difference as an exception to done line 2 for the owner.
4. `skills/workflow-delivery/scripts/skip.py` (new, shipped with the skills):
   - `lane(base, head, name)`: the lane skip. It applies only when GitHub runs this repo's tests; otherwise the lane runs and says why (the conditions are in the code and pinned by the toy). A dirty tree is refused with `LANE_DIRTY`; a live lane is never replaced. It returns `("skipped", SKIPPED line, [])`, writes the line first in `<step>-lane.txt`, writes `.last` with state `skipped` (not terminal) and the head in `<step>-lane.skip`. It writes no `.ok`.
   - `accepts(runs, slug, step, head)`: read by `lanekit.lane_ok`. It returns `head` when `.skip` holds that head and GitHub's check runs on that exact head are acceptable (a failing `gh` is a refusal). The exact rule is pinned by the toy and is pending top's ruling.
   - `check(g, slug)` and `regen(g, slug)`: at `goal.py pr` the generated files are CHECKED and never rewritten there. A stale file prints `NOTE: REGEN_STALE: <files>` with the ordered Fix.
5. Who writes generated files now (the lane no longer does for a skipped goal): the writers are the existing commands, named in the Fix line and run by the worker at ship: `entry.py write`, `wiki.py prepare SLUG --commit`, and the Tests-table render that `lanekit.prep` runs today. The `docs-check` quick check refuses a stale page at push, before the PR, so the worker finds out at the push and not at the pull request; pages stale only by commits since their stamp are restamped by `wiki.py prepare SLUG --commit` (DOC-2). The earlier claim that the lane restamps them is withdrawn. `REGEN_STALE` is a note at `goal.py pr` in v1.1.0 and becomes a hard stop in v1.2.0 after #5728 and #5783.
6. Version bump: `goal.py pr` keeps today's order (the regen check, then the bump). With `pr_bumps_version` on (default false) the bump is the one commit `pr` can make and DEL-25.4's "head unchanged" does not hold for that setting; the PR notes say so and the toy asserts the default. If top wants the bump to refuse instead of commit, that is a small separate change.
7. Edits to existing scripts, each measured on committed LF bytes after the merge-up: `lane.py` (import `skip`, the one call, `lane_checks` via `importlib`); `lanekit.py` (`lane_ok` calls `skip.accepts`; docstring line 5 reads "after its lane"); `fit.py` (`regen` is `import skip; return skip.regen(g, slug)`); `goal.py` (regen check before the bump, `gate == "pass" or None` to `private.pr_result`); `private.py` (`pr_result` returns at once with `STATUSES none` for `ok is None`); `seed.py` (item 3). The branch still carries three earlier commits with refused trims and a `dev/` loader; the build adds a plain commit that restores those files from main and removes `dev/skip.py`, `dev/quick.py` and the loader; if a push of that is refused, no force push is made and the operation is asked.
8. Rows, ONE PER TEST SCRIPT (REG-4): three rows, `fast-checks-quick`, `fast-checks-lane` and `fast-checks-regen`, each tier `land`, each keyed to the FEATURE ID (`DEL-25`, re-keyed after fast-text-2; until then `v110-fast-checks:1`), the sub-ids in each description. The earlier single row and its driver script are dropped. Net +3 on a table already over the 600-row cap and past TD625's net-zero rule: the PR asks the operation for either a net-zero merge of three existing rows or a TD815 grant, and the build does not add the rows before one is recorded.
9. Docs: How-to-use-Delivery (quick checks, install, tests on GitHub) and Tests-table entries; `docs.py check` clean.
10. `design.md` is rewritten to this plan (one script, one hook, no `local_lane` setting, a new file under `skills/`, one row).

## PR notes (stated, not hidden)

- `.ok` is a tested pass only; a skip is recorded apart and `lane-wait` exits 3 for it.
- The real-push case needs network (it skips with exit 77 when offline) and the pip install counts toward suite time; it runs on the Mac and Linux only.
- The private-name scan runs as pre-commit's legacy hook, not as a framework hook (ruling 4); native Windows runs the stub alone; adopted repos get the quick checks through `quick.py install`.
- DEL-25.1's metric (pushes that skipped the checks) is not measurable, since hooks are per clone and nothing counts them.
- `pr_bumps_version` (item 6) and `REGEN_STALE` as a note (item 5); DEL-17 against DEL-25.3 (ruling 6); the over-cap row table (item 8).
- Windows-only cases: the PR names every case that did not run on Windows and says where it ran.
