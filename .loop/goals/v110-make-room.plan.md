### 1. The mechanism (one rule for all seven moves)
- A moved function goes whole, with its decorator lines and its text unchanged, into a new sibling module in the same folder. The names it used from the old script become `_s.NAME` (the module prefix). The alias is `_s`, never `g`: goal.py's `round_stop` already takes a parameter named `g` (the goal module), and part B's fit.py has six more, so a `g` alias would shadow it and `g.NAME` would raise.
- The new module imports its script at the BOTTOM of the module: `import <script> as _s  # noqa: E402`, after every def. The function bodies read `_s.NAME` only when called, so the import order never matters at call time, and importing a new module first (`import goal_steps`) works: the script's `from <new_module> import ...` at its end finds the module already complete.
- The old script re-exports the moved names with one line at its very end, after its last definition and before its `if __name__` block: `from <new_module> import NAME1, NAME2  # noqa: E402,F401`. Every caller (`merge.advance`, `lane.finalize`, `goal.cmd_pr`, the toys, the guard code) still finds the same name on the same module, so no caller changes.
- Registration: a script run as `python3 script.py` is `__main__`, so it registers itself under its module name with `sys.modules.setdefault("<script>", sys.modules[__name__])` (goal.py already does, as ME). The line goes BEFORE the first import in that script that can import it back (found by the build with a grep of the script's imports), not at the end. flow.py, lane.py and merge.py each gain that one line.
- One naming rule (the manifest and the move check apply it the same way): a name moved with the function into the same module is a plain name (sibling, no prefix); a standard-library module the function uses (os, re, sys, time, subprocess, json, and so on) is imported by the same statement at the top of the new module and used as before, with no prefix; EVERY other top-level name of the old script that stays there (its own functions, constants, ME, FLOW and the like, and shims such as lane.py's `fcntl = lanekit.fcntl`) is `_s.NAME`. A shim is never replaced by a real import: lane_run.py uses `_s.fcntl`, never `import fcntl` (test-windows-safe.py flags an unguarded `import fcntl`). Builtins are ignored.
- A new module runs alone (the package rule): `python3 new_module.py --help` imports its script (which imports the module back) and exits 0 with no output.
- The header of every new module is exactly: a one-line docstring saying what the module holds, its standard-library imports, the DEL-10 guard line (only when the module mentions `subprocess`: it is the same `os.environ.update(GIT_TERMINAL_PROMPT=...)` line the existing scripts carry, because the package rule test-rows.sh DEL-10 requires it in every script that starts a process), then the moved functions in table order, then the `_s` import. The docstring, the guard line, the registration line, the `_s` import and the re-export line are the ONLY lines in the whole goal that are not a byte-identical move (the "header exemption"); the move check allows exactly those and nothing else.
- Docstrings (one line each): goal_steps "the record and pr commands"; flow_steps "the step runner and the prompt builders"; lane_run "the lane finish, status and wait"; merge_steps "the merge steps: base check, release advance, issue filing".

### 3. The move check (dev/toy/move-check.py, new; dev/toy/test-make-room.sh runs it)
- The manifest (dev/toy/move-manifest.json, committed) is DERIVED, never typed: `move-check.py --derive` reads each moved function's free names with ast, marks every name defined at top level in the old script and not moved with it as `_s.NAME`, treats names moved to the same module as siblings, and writes the manifest; the check recomputes it and fails if the committed manifest differs. The base text comes from `git show <B>:<path>`, where B is the comparison base recorded in the manifest: it starts as 189d1c831 and moves to the origin/main commit most recently merged in (recorded by a docs-only commit each time the build merges main), so a change main makes to text that is NOT moved never turns the proof red, and a change main makes to a MOVED function after its move began STOPS the goal (the operation decides). Rows 2 and 4 compare the moved functions and the help/constant surface against 189d1c831 for the functions' text, and the remaining text against B.
- For every moved function it proves: (a) `ast.dump` of the new function, after removing the `_s.` prefix from the manifest's names, equals `ast.dump` of the base function; (b) the source text equals the base text once those prefixes are removed; (c) the function is gone from the old script and present in the new module exactly once; (d) the old script re-exports it by name.
- Header exemption proof: parsing each new module, removing the docstring, the imports, the guard line (exact text), the `_s` import and the moved functions leaves nothing; parsing each old script, removing the moved functions and the five header lines (registration, re-export, imports) leaves the base script's remaining text byte-identical.
- Whole-file proofs run on committed text, never the working tree once the move is complete: during the build they compare the working tree with 189d1c831; after the last move the toy reads the pinned head sha (the same sha row 2 uses) so a later `git merge origin/main` that touches non-moved text never turns this toy red; the build re-pins that sha with a docs-only commit after any re-merge of main before the pr. The set of string constants of the old script plus its new module, minus the header exemption (docstring, the two registration strings, the guard line's constants), equals the base script's set (no output line, flag, command or setting name changes); `python3 script.py --help` for each of the four scripts and every argparse subcommand prints the same text as on the base; every name the base script defined at top level is still defined there (by definition or by re-export).
- Negative controls (seen red): change one byte inside a moved body; drop a re-export; rename a moved function; add a string constant; add a non-header line to a new module; use `g.` for a name: each makes exactly its own check fail.
- Size proof: size-check on the four scripts and the four modules: each at most 13,000 bytes, every script under 20,480.
