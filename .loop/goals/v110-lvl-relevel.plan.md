### The shape, and why (read from the code on main 73c7bdbae)

- The table is `.loop/regression.tsv`, read by `regression.read_rows` (regression.py:83) and written by `edit_rows` with `FIELDS = (id, level, command, goal, seen_red, description, category, link)`. A hard swap of the word in column 2 would touch about 75 files, which is four goals' worth and fails the 20-file rule.
- So this goal ADDS the new words in three new columns appended after `link` and leaves the old `level` column and every reader of it alone: `stage` (L0, L1 or L2), `risk` (security, private or none) and `covers` (the machine-readable list of row ids a covered row is proved by, comma separated). The old word stays in `level`, so the re-levelling record's "old word" is real. G2 and G3 move the run rules onto `stage`; the old column and its words are retired by a later goal once nothing reads them. `goal_levels`, `ci_levels`, the PR workflow's level map and the Regression runbook's labels keep the old words in this goal; their change belongs to the swap that retires them (LVL-1.5's last bullets), and this plan says so rather than hide it.
- The new refusals are ARMED by an explicit marker, not by the data (red team CEO, Codex 2): the file `.loop/regression-relevel.tsv` exists. A fixture table, an adopted repo's table or a table that was never re-levelled has no such file, and reads exactly as today. Once the record exists (it is written by the re-levelling and committed with the table), every row of the table must have a valid `stage` and `risk`, and a blank or "L3" stage on any row, even every row at once, is refused; clearing the stages does not disarm it, only deleting the tracked record does, and that is a visible diff. `regression.py add` and `regression.py sync --write` in an armed table give a new row a stage and a risk (below), so a new row cannot arrive untagged.
- How the frozen done lines read: done lines 1 and 2 say "level"; in G1 they are tested on the new `stage` column (and `risk`) of an ARMED table, which is main's table after the re-levelling and the toys' armed fixtures; an unarmed table is outside them by design. The old `level` column is retired by a SEPARATE goal, G4, which also carries the old words in `goal_levels`, `ci_levels`, the PR workflow's level map and the Regression runbook's labels, and the separate draft state column; this goal does not do it.

### Steps

1. `skills/workflow-regression/scripts/levels.py` (NEW, about 5,500 bytes, stdlib only): `STAGES = ("L0", "L1", "L2")`, `RISKS = ("security", "private", "none")`, `check(rows, root)` and `relevel(root, times)`. `check` returns nothing for an unarmed table (no record file); for an armed one it refuses, one line each and the first failure exits 2, with these codes: `LEVELS_BAD_STAGE` ("row <id> has stage <word>; the levels are L0, L1 and L2", for blank and for "L3"); `LEVELS_NO_RISK` ("row <id> guards Principle 6 requirement <ID> and has no risk tag; the tags are security, private and none"); `LEVELS_BAD_RISK` for a word outside the three; `LEVELS_BAD_COVERS` ("covered row <id> lists <x>, which is not a row id"); `LEVELS_NO_EVIDENCE` (a defect row's issue labels could not be read at the re-levelling); and `LEVELS_L0_OVER` ("the L0 rows add up to <n> seconds; the limit is 45"). `check` is armed by `.loop/regression-relevel.tsv` existing, not by the stages. Every refusal prints the exact fix: the row's line to write, and who acts (the worker edits the row).
2. The Principle 6 rows and the risk tag, with real sources (the first draft named inputs that do not exist): a row guards a Principle 6 requirement when its `goal` column names a requirement id in the Principle 6 table of `docs/wiki/Principles.md` ("## 6. Private and guarded", read, never edited, four requirement rows today); adding a requirement to that table arms the rule for its rows. Its tag is `private` when the requirement's own summary text in that table holds one of the words `private`, `private name`, `leak`, `home path`, `secret` (a fixed list in `levels.py`), else `security`; the tag and its reason (`risk: requirement`) go in the record. A defect row's tag comes from the linked issue's labels, read ONCE by the re-levelling with `gh issue view <number> --json labels` for each of the 130 defect rows (the one network read of this goal, never made by a test): a label named `security` gives `security`, `private` gives `private`, any other gives `none` with the reason `no security label`; if `gh` cannot be reached or answers an error for a row, the re-levelling REFUSES to write and names the row (`LEVELS_NO_EVIDENCE`), so a defect never turns `none` for want of evidence. `regression-issues.tsv` is not used (it holds only link, state, date and reopened_at). A Principle 6 row must have `risk` security or private; a row with `none` or blank is refused (`LEVELS_NO_RISK`), at any time, not only at the re-levelling.
3. `regression.py` (20,447 B, 33 B left) gets, in order: `FIELDS` gains `stage`, `risk`, `covers`; `read_rows` calls `levels.check(rows, root)` once; `cmd_add` takes `--stage` and `--risk`; `draft()` (regression.py:104, which `regression.py sync --write` calls to draft a row for a done line with none) gives the row `levels.draft_fields(root, goal)`: stage L1, and risk `security` for a Principle 6 requirement and `none` otherwise, so the draft workflow keeps working on an armed table; a new subcommand `relevel [--dry-run]` calls `levels.relevel`. To pay for this without trimming text, the two self-contained whole functions `merged` (502 B) and `split` (501 B), which use no name from regression.py and are called only by `cmd_run`, move whole into `completion.py` (1,909 B), with one re-export line in regression.py; the move check covers both.
4. The re-levelling (`levels.relevel`), applied to the 744 rows, never drops or reorders a row, writes `stage`, `risk` and `covers`, and writes `.loop/regression-relevel.tsv`, one line per row: `id TAB old word TAB new stage TAB risk TAB reason`. The rules, as the approved page gives them (LVL-1.5): `land` becomes L1 by default; a `land` row goes to L0 only when its measured time (the 656 measured times in `.github/workflows/row-times.tsv`, read, never edited) is under 5 seconds, its command script uses no network and no toy repo (a fixed word list in `levels.py`: `dev/toy/make.sh`, `gh `, `fakegh`, `git push`, `git clone`, `git init`, `curl`, `urllib`), and adding it keeps the L0 total at 45 seconds or less (rows are taken fastest first until the next would pass 45); a row with no measured time starts at L1; `nightly` becomes L1 when its measured time fits an L1 shard and L2 otherwise, where "fits" is the pull-request row limit that exists today, 200 seconds (the run's row limit, `lanes`/`regression-limits.tsv`), and a row that `.loop/regression-limits.tsv` keeps out of the PR shards with the word `nightly` becomes L2 whatever its time; a nightly row with no measured time follows the page's untimed rule and starts at L1 unless that file keeps it out. All 27 nightly rows have a measured time at or under 200 seconds today, so only the limits-file rows go to L2, and the rule is stated so a future row is decided by data, not by taste; `covered` is not a run of its own: `covers` is the list of row ids that prove it and its stage is the highest stage among them. On main 13 of the 23 covered rows name existing rows in their command or description text and `relevel` fills `covers` from those; 10 do not (`done-hard-eta-2`, `done-judge-stable-keys-2`, `done-apply-rerender-2`, `done-homeguard-skills-main-1`, `done-homeguard-skills-main-2`, `done-docs-v2-3`, `done-docs-v2-4`, `done-docs-v2-5`, `done-docs-v2-6`, `done-gap-wave1-small-4`: their text names a row that was renamed or is absent, or uses a wildcard). So the build starts with a COVERS PRE-PASS: for each of those 10 the worker reads the row, names the existing rows that really prove it, writes them in `covers` by hand, and records `covers: by hand` as the reason; the reviewers see the ten mappings. Merely keeping references that happen to exist is never enough: a row whose list drops part of the claimed proof is listed with the full text beside it. A row for which no existing row can be named stops the build and asks the owner (`LEVELS_BAD_COVERS` stays refused, never guessed); `draft` has no row on main, so the separate state column for drafts is not built here and is left to the swap that retires the old words. Risk: every row that guards a Principle 6 requirement is tagged security or private (private when its requirement is under the Private-data rows, else security), every other row is `none`, and every Principle 6 row has stage L1 at the lowest (the minimum level), so it is never L0 or L2-only. The reason column is one of `time`, `risk`, `default`, `covered` or `no time`.
5. The L0 total check: `levels.check` sums the measured times of the stage-L0 rows (from the times file) and refuses over 45 seconds, naming the total (`LEVELS_L0_OVER`); `relevel` runs it before writing and refuses to write a table that fails. A row at L0 with no measured time is refused too (it has no time to add).
6. CBS-1's table (done line 5): the size table `checks_by_size` in `sizing.py` gets a `levels` key per size (default: small and medium `["L0", "L1"]`, large `["L0", "L1", "L2"]`, the page's "a size may add a level but never drop L0 or L1; a large goal adds one L2 run"). `sizing._validate` refuses a size whose `levels` leaves out L1 or L0 (`SIZING_BAD_LEVELS`: "row <size> leaves out L1; every size keeps L0 and L1"), naming the size and the level, and it keeps the `levels` key out of the check-form loop (it iterates the row's checks). A table with no `levels` key reads as the defaults, so no repo's config breaks. `cutcheck.py` already calls `sizing.validate`, so the cut sees the refusal too.
7. Docs, text only: `skills/workflow-regression/SKILL.md` gets one command-map line for `relevel` and the new `add` options; `skills/loop-files.md` gets the three new columns and the new codes in the regression.tsv section; `listing.json` gains the `relevel` command line.
