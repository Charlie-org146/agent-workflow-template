### 1. The mechanism (part A's rule, unchanged)
- A moved function goes whole, with its text unchanged, into a new sibling module in the same folder. Names it used from the old script that stay there become `_s.NAME` (the alias is `_s`, never `g`: fit.py has six parameters named `g`). A name that moves with it into the same module is plain; a standard-library module it uses is imported again in the new module; builtins are ignored. The prefix lists are DERIVED by `move-check.py --derive`, never typed.
- Each new module ends with `import <script> as _s  # noqa: E402`; each script re-exports the moved names with one line at its end (`from <module> import ...  # noqa: E402,F401`) and registers itself with `sys.modules.setdefault("<script>", sys.modules[__name__])` before its first import that can import it back.
- Header of each new module: a one-line docstring, its standard-library imports, the DEL-10 guard line where the module mentions `subprocess`, the functions in table order, then the `_s` import. Those lines, the registration and the re-export are the only lines in the goal that are not a byte-identical move.
- Moved bodies use none of `__file__`, `__name__`, `traceback`, `inspect`, `_getframe`. That keeps `fit.tool` (reads `__file__`) in fit.py and `routing.cmd_finish` (reads `__file__`) in routing.py.
- Docstrings: fit_budget "the regen, pull request and owed text of a goal"; role_gate "the record step, its gates and the lane caps"; routing_pick "the agent build, detect and check commands".
