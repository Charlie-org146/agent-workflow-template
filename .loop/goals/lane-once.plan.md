# Plan: lane-once

## Implementation plan

Checked against the code. `need_lane` (role.py) reads `<slug>.<step>-lane.ok` for the step being recorded (goal.py record qa and ship). `lane()` (lane.py) returns an earlier pass only from the same lane name. All three names run the same command (`lane_argv`: `regression.py run land --reuse --tier goal`), so a pass at a head by one proves the other two. `flow.py` runs `role.lane` for the qa and ship steps before it prints NEXT, and `goal.py pr` runs `role.lane(..., "pr", ...)`. The PR body reads the pr lane's `.last` and `.txt` (`lane_part`).

This plan replaces an earlier one that copied the pass into the other names' records (path A); the red-team gate rejected that, and it is reverted by revert commits. The done lines are the five frozen lines in `.loop/goals/lane-once.md`. The steps below are the whole plan.

Build steps, in order:

1. lanekit.py gains `LANES` (the one list of lane names), `lane_base(runs, slug, name)`, `lane_ok(runs, slug, step, head)` returning `(text, lane)` (the step's own `.ok` first, then the other two; the first that holds `head`, else the first text any left) and `passed(runs, slug, head, name)`: the lane with a complete pass at head (`.last` says pass at head and its `.ok` holds head; own first, then qa, ship, pr), else the own lane when only its `.last` passes (a record from before this change, as today). Nothing is written.
2. lane.py: `NAMES = lanekit.LANES`. In `lane()`, with no job held, a clean tree and `fresh` false, a pass from `passed()` is returned as `("pass", <that lane's line>, [])`, with `; reused: the <lane> lane passed on this head` added to the returned first line when it is another lane's; no file is read for writing or written. `lane_status()` (used by `lane-wait`) first reports running for a live sibling job at this head and finalizes a sibling job that ended at this head, then answers the same pass. `lane()` takes `fresh=False`; `role.py lane SLUG NAME --fresh` passes it: it refuses with `a lane of SLUG is still running` while any job of the slug is live, else removes the three `.ok` files of the slug (the tool does it, no hand edit) and starts a lane as if no pass existed, so the gates then wait for that lane's own pass.
3. role.py: `need_lane` calls `lanekit.lane_ok` in place of reading the step's own `.ok`; the refusal reads `HEAD moved since the <lane> lane passed (lane on <h>, HEAD <h2>)` naming the lane that last passed (own-name text is byte-identical to today); LANE_MISSING, the fix lines and `over_caps` are unchanged. `lane_note` reads the `.last` of the lane whose `.ok` satisfies the gate (own first). `lane_part` reads the `.last` and `.txt` of the lane whose `.ok` equals HEAD (the pr lane first, so a pr lane that ran after a base merge always wins over an older qa record, and a pass at an older head is never shown), and, when it is not the pr lane, says `(lane: qa, ended <UTC time>)` after the LANE line, from the record's `ended` field, so the PR body shows which lane ran and when.
4. Row selection is untouched: `lane_argv`, `prep`, the planner, the tests tables and the budgets are not edited.
5. New toy `dev/toy/test-lane-once.py` with one regression row (category defect, linked to issue 5734, seen failing by `regression.py red` with a break command that cuts reuse to the own lane). The toy builds a throwaway git repo with hand-written lane records; `lane.prep` is a counting stub so no row runs. Cases: (a) a qa pass at HEAD answers ship and pr with no lane started and no file written; `need_lane` accepts ship; `lane_note` and `lane_part` read qa's record and `lane_part` names the qa lane and its end time; (b) controls: HEAD moved (HEAD_MOVED names the lane that passed and both heads, `lane ship` starts a lane), a failed qa lane, a pass at another head, a dirty tree (no reuse in `lane()`; `need_lane` unchanged, recording today's behavior), no pass at all (LANE_MISSING); (c) an incomplete record (`.last` pass, no `.ok`) is not a pass unless it is the own lane's, as today; (d) `lane` and `lane_status` give the same answer over own fail plus sibling pass, a dirty tree, a live sibling job and a sibling job that ended unfinalized; (e) `--fresh`: after a qa pass, `lane ship --fresh` removes the three `.ok` files and starts a lane, and `need_lane` then refuses ship until that lane passes; (f) the three names run one argv: `lane_argv` takes no lane name and `lane()` builds its command from it once; (g) the reuse-cut control: the same steps against a temp copy of the delivery scripts whose `passed()` answers only the own lane must fail case (a) because a lane would start (the `prep` counter is 1); the toy fails first if the text it cuts is not found, so a refactor can never turn the control into a no-op; (h) done line 2, as a real test: `lanes_cli.py affected` is run for the same changed paths with this tree's regression scripts and with those of the base ref (`git archive` of origin/main, else main), and the `AFFECTED` and `ALWAYS` lines must be identical and non-empty; the toy fails, with the fix named, when the base ref cannot be resolved (it never skips).
6. Two existing assertions follow the behavior they described and are named in the PR body: `dev/toy/test-lanes.sh` (ship now answers from qa's pass: the output holds `; reused: the qa lane passed on this head`, no `ship-lane.job` exists and the recorder ran once for this commit; it still fails if ship starts a lane) and `dev/toy/test-prep-budget.sh` (the rerun passes with `LANE pr` or the ship lane it reuses). `test-lane-control.sh` holds as written.
7. Docs: `skills/loop-files.md` states one lane per head, the reuse sentence with a two-line transcript, the pr caveat (a base merge that moves HEAD needs a new lane), that `need_lane` does not check a dirty tree (as today), and `--fresh`; the Tests tables are re-rendered and the own pages restamped (stamp lines only).
8. Only lane.py, lanekit.py, role.py, `skills/loop-files.md`, the new toy, the two toy assertions, `.loop/regression.tsv`, docs stamps and this goal's records change; no new file under skills/. Sizes: the bytes quoted by reviewers (lane.py 20,325, lanekit.py 20,454) are the reverted path A build; the starting sizes are lane.py 18,716, lanekit.py 19,548, role.py 19,997, and the budget for this change is lane.py at most 19,100, lanekit.py at most 20,250 and role.py not larger than today, measured after the build (a build over a budget is cut down, not reformatted to fit); each of the three scripts stays under 20,480 bytes; the change adds no record field, no file name and no state, so old run records read as before.

What could break:
- A pass returned from another lane's record has no copy to keep in step: the lane that ran owns it. Two readers disagree only if `lane` and `lane-wait` disagree; case (d) pins that.
- `goal.py pr` merges the base first, so HEAD moves whenever main moved and a new pr lane runs; that is the stated rule. The saving is certain for qa to ship and for pr only when main did not move.
- A pass with rows this machine cannot run is reused with its `N pass; M not runnable here` note, which `lane_note` reads from the lane that ran; `--fresh` retests.
- `.ok` is written by the lane only after a pass, and a pass is complete only when `.last` and `.ok` both say so (the gate reads `.ok` alone, as today); `.ok` and `.last` live in this machine's runs folder, so a pass never crosses machines. A runner or package upgrade does not change HEAD; the key stays the exact head, as done line 1 says (taste, listed).

Out of scope: lane budgets, row selection, the flow file, `merge`, the lane child, a dirty-tree check inside `need_lane`.

PENDING: none for the owner.
