# Plan: v120-confidence-subs (second half of #5790; owner o312; TD945)

Depends on v120-confidence-known (pc-w4, branch loop/v120-confidence-subreqs, plan 24c116e9f): same `sections.confidence()`. PLAN now; BUILD only after that change is on main, then rebase and re-measure bytes.

## Idea
A feature's confidence today counts rows keyed to the feature's top ID (`[DEL-3]`). Sub-requirements ("  - ... [DEL-3.n]" bullets under a requirement) are not IDs, so a row cannot name one and one untested sub does not lower anything. Make `DEL-3.n` a real, linkable ID, count its rows, and never show 100% while a declared sub has no passing row, naming it.

## Findings from the code (verified at origin/main 7b3155d90)
- `criteria.ID = ^[A-Z]{2,5}-\d+$` (criteria.py:40) decides whether a regression row's goal or id links to a requirement (`test_rows`, line 131); `linked` keys feed the Tests table and the "rows link to X, which no page has" check (line 278). `seen` is built from `^- ID: **` lines only, so a sub ID is "no page has" today.
- `sections.confidence` matches `\b[A-Z]{2,5}-\d+\b` on the row's bracket text and compares `t[3] in ids` exactly.
- Sub bullets today carry the parent tag (`[DEL-3]`, Delivery.md:24); v120-del3-text writes `[DEL-3.n]`.
- Sizes (LF bytes): sections.py 11,575, render.py 18,737, criteria.py 20,455 (25 bytes under the cap), pageformat.py 18,933, docs.py 18,458, counting.py 18,948, docs.py, pageformat.py. No file may newly cross 19,000 or 20,480 (GRD-20, no trimming); a crossing is a stop and report.

## Meaning
1. Declaration: only in the page's `## Requirements` section, outside code fences, as an indented line (the new `declared(text)` scans the raw lines, tracks fences and stops at the next `## `, because `sections.body` strips indentation and does not skip fences, so it cannot be reused as is)  `^\s+- .*\[([A-Z]{2,5}-\d+)\.(\d+)\]\s*$` whose parent `ID` is a requirement declared on that page. Text under Retired, Non-goals, Success metrics, Revisions, Tests or in a fence is never read (done line 3). A sub whose parent is Retired/moved is not declared.
2. ID grammar widens to `^[A-Z]{2,5}-\d+(\.\d+)?$` in `criteria.ID` and the Tests-page link path (one shared constant, not copies). A row id or goal `DEL-3.2` links; `DEL-3.2` with no declaring page reports "rows link to DEL-3.2, which no page has" exactly as for a top ID.
3. Confidence per feature row (`[DEL-3, DEL-6]`): counted rows are those keyed to the row's IDs and to every declared sub of those IDs (`t[3] in ids ∪ subs`); a row keyed to a sub counts once. Format `NN% (P of T)` unchanged.
4. Cap: if any declared sub of the row's IDs has no PASS row, the shown value is `min(value, 99)`; `round()` would show 100 at 99.5+, so compute as `min(99, round(...))` only when a sub is untested. The same cell names it: `99% (P of T; untested: DEL-3.4, DEL-3.7)`, list cut after 3 with "+N". A sub counts as tested only if a counted row for it has latest state PASS. FAIL, SKIPPED and never-run are untested. With v120-confidence-known on main, KNOWN is not passing for the cap as for the score (stated rule: a FAIL plus KNOWN row without any PASS is untested).
5. UNDATA ordering: no counted rows at all stays UNDATA even when subs are declared (nothing measured); the cap and names apply only once at least one counted row ran. A feature whose subs exist but whose only rows ran green on the parent keeps its parent score capped at 99 and names every untested sub.
6. No declared subs: byte-identical old string (done line 4).
7. Links: README and Home resolve the same Tests anchors for sub IDs, including `blob/main/docs/wiki/*.md` and `(docs/wiki/` forms (the `LINK` regex in sections.py already strips them); one toy asserts both pages render the same cell.

## Revision 5 (the Mac's gate 4 on f71f08764; supersedes Revision 4's `vouched` rule)
- Scope first (binds everything below): the cap, the names and the digest apply ONLY to a feature row whose IDs have at least one declared sub. A row with no declared subs returns exactly the old string, in live and in keep mode, whatever T and n are (done line 4; DOC-2 14 of 14 against 16 rows and REG-4 51 of 51 against 57 stay as they are). S4 asserts that a row with no subs and T < n stays uncapped in both modes.
- Vouching by the set, not the count. For a feature row with declared subs, the cell carries a short digest of its inputs: the first 6 hex of sha1 over the sorted ids of the non-draft rows keyed to the row's IDs and their declared subs, a separator, and the sorted declared sub IDs. It is written as an HTML comment inside the cell, `<!-- s:1a2b3c -->`; a render never writes it for a row without subs. S18: the docs check, the format checks and the wiki render accept a digest comment in a Confidence cell. If the format checks refuse comments, the build stops there and reports; the only fallback is a visible 6-hex token, decided with operation-pc, not invented.
- Keep mode: when the kept cell's digest equals the digest recomputed from today's rows and declared subs, the cell is returned byte for byte, names, `+N` and digest included. So a live render followed by `render --check` is a no-op however many names it shows (S17d: more than 3 names, with the hidden ones a row-less sub and a FAIL sub), and a stale 100% cannot survive a row fold or a sub added in the same change (S17e: one row folded and a FAIL sub row added; the digest differs, the cell is capped). When the digest differs or is missing the cell is capped at `min(99, kept)`, names are the kept visible names (still declared) merged with the static names (declared subs with no non-draft row), cut at 3 then `+N` over the union, and a live render replaces it. A kept `not measured: no data yet (untested: ...)` cell has no percentage: it stays in the not-measured form with the names merged (S8 round-trips it, digest matched and unmatched).
- Live mode: names are the declared subs with no non-draft PASS row; the value is the plain share, capped `min(99, ...)` only when a name exists. T == n is no longer a test, so the Mac's cases where every sub passes but a parent row is SKIPPED or on another platform, a nightly row is missing from the run, or a row was added since give plain `100%`, never a bare `99%` with no reason (S17c now asserts 100% in both modes). The previous question of how often it caps without a name is moot: it never does.
- The claim "a render with or without gh gives the same cell" holds only while the run results have not changed since the cell was made: with gh a sub row that went PASS to FAIL changes the cell, without gh the digest still matches and the cell is kept. ## Revision 9 (the Mac's question on "at once" versus the honest limit; gate 7)
Answer, plainly: "at once" is true for the LIVE render and false for main.
- Where the percentage is computed from run results: only in a live render, `sections.fresh` with a readable full run (`latest_full`, `gh`). A live render happens when someone runs `render` (docs.py:316, render.py:391; the lanes and `publish` run it) and is committed with that change; no workflow in this repo renders the README, Home or Principles cells on a timer (`regression.yml` runs the full suite every 4 hours, `17 */4 * * *`, and records results; it does not commit those cells). So the cadence of the next live render is "the next goal that renders or publishes", not a fixed interval, and I cannot promise one.
- What main shows between live renders: yes, a committed page can show `100%` for a feature with a declared sub that has since gone FAIL, and the docs check (keep mode) stays green on it, because keep mode reads no run result. So TD1020 (2) "drops at once" holds at the next live render and does not hold for main in between.
- What closes it, and its cost (a choice for top, not taken here). The repo already commits per-row states in `.loop/regression-runs.tsv` (`id status date run flaky`; the Tests tables already render from it through `ran_of`, so the Tests tables already go STALE when it changes). In keep mode `sections.fresh` would read that file the way it already reads `regression.tsv` and apply the live rule with those states: a declared sub with no non-draft PASS row there is named and the cell is capped. The docs check then reports STALE (differs from a fresh render) as soon as a FAIL for a sub is committed in that file, until someone re-renders. Cost: about 150 to 200 bytes in sections.py (11,575, room about 7,400), none in criteria.py or render.py; one case S11b (a sub FAIL in regression-runs.tsv with a committed 100% makes the check STALE; control: the check without the file read stays green).
