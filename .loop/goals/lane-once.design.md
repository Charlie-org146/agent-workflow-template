# Design: lane-once

Generated by /office-hours (condensed, no live questioner) for goal lane-once; revised for path C after the red-team gate

Mode: Builder (internal tooling)

## Problem Statement

Each step's lane gate reads its own `<slug>.<step>-lane.ok` (`need_lane` in role.py), and `lane()` in lane.py reuses only the same name's pass. The qa, ship and pr steps run the same command (`lane_argv`: `run land --reuse --tier goal`) at the same head, yet each starts its own lane. Reviewed DEL-17 promises one lane per head (issue #5734).

## Constraints

- Done lines frozen: one lane per head, its pass satisfies the qa, ship and pr gates; any HEAD move needs a new lane; row selection and budgets unchanged; a head mismatch or a failed lane still refuses, with a negative control; no new file under skills/.
- lane.py, lanekit.py and role.py sit at the 20,480-byte script cap (lanekit.py 19,548, role.py 19,997, lane.py 18,716): the change must be small.

## Premises

1. The three lanes run an identical command, so a pass at a head by any one of them proves the other two.
2. A pass is the lane's own record; nothing is copied, so no record is ever half-written, and no field or file name is new.
3. A step that needs a real run of its own lane has a sanctioned command, not a hand edit.

## Approaches Considered

- A. Copy the pass into the other names' records. Built first; rejected by the red-team gate: copy and partial-copy states, a suffix contract, `.prev` files, size pressure.
- B. One shared file `<slug>.lane.ok`. Rejected: renames every reader and loses old runs.
- C. Read, don't copy (chosen). `need_lane` accepts the `.ok` of any of the three names when it equals HEAD; `lane()` and `lane_status()` answer a pass from any name's complete record; `lane_part` and `lane_note` read the passing lane's files directly; `role.py lane SLUG NAME --fresh` forces a lane.

## Recommended Approach

C. Controls: a qa pass at H lets ship and pr answer pass with no lane started and no file written; a HEAD move, a failed lane, a pass at another head and a dirty tree each start a lane or refuse; the rows selected for the same diff are identical to main's.

## Open Questions

None for the owner.

## Success Criteria

- With a qa pass at HEAD, `role.py lane SLUG ship` and `pr` return the pass and start no lane; the ship gate in goal.py accepts it.
- HEAD moved, or the qa lane failed: refused as today.
- Existing lane toys stay green; sizes under the cap; docs, package and private-name checks green.
