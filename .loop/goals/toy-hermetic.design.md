# Design: toy-hermetic

Generated by /office-hours (condensed, no live questioner) for goal toy-hermetic
Branch: loop/toy-hermetic
Status: DRAFT
Mode: Builder (internal tooling)

## Problem Statement

`dev/toy/test-platform-limits.py` and `dev/toy/test-machine-log.py` read the Mac's live session state: host and session variables, the real HOME and the real git common dir. On a Mac where an operation session is running, the rows `platform-sends-counted` (#5700) and `machine-status-live-workers` (#5671) fail in qa lanes, and pass on CI where none of that state exists. Each failure costs a goal a try. The toys must run the same everywhere, without weakening any check.

## Constraints

- The done lines are frozen: each toy fails as today with the Mac's real state and passes under its own hermetic setup; every assertion is kept, none skipped, and a control proves each toy still fails when its subject is broken; only the two toys and the goal's own records change.
- A toy must never write the checkout's own operation id file (a loop-level file, shared by every worktree of the repo).

## Premises

1. The leak is in the toys, not in the scripts they test: the scripts correctly read host and session state; the toys must not hand it to them.
2. A scrub done inside each toy (unset the variables, point HOME at a throwaway directory, run from a fixture) is enough, because both toys already build a fixture repo.
3. The rows and their commands stay as they are, so the fix is invisible to the regression table.

## Approaches Considered

- A. Scrub inside each toy (chosen). Each toy drops every `CLAUDE*`, `ANTHROPIC*` and `LOOP_*` variable and `GIT_DIR`, `GIT_COMMON_DIR`, `GIT_WORK_TREE`, sets HOME and USERPROFILE to a temporary directory, and runs its subject from the fixture's directory. Effort S, two files, no new surface.
- B. Shared helper module for the scrub. Rejected: a third file breaks done line 3, and two small blocks do not justify a shared contract yet.
- C. Wrap the rows in `env -i` in the regression table. Rejected: it edits the table, hides the leak instead of fixing the toys, and diverges from how the toys run by hand.
- D. Skip the toys on the Mac. Rejected: it removes the checks, which done line 2 forbids.

## Recommended Approach

A. Each toy also gains controls that prove the scrub works and can fail:
- machine-log: a host session id left in the environment makes the wait loop claim an operation session, and the claim lands only in the fixture; with the scrub no claim happens; the checkout's own operation id file hashes the same before and after.
- platform-limits: with a host session id and GIT_DIR set in the parent environment the fixture still counts its send; the checkout's own operation id file hashes the same before and after.

The hash check reads the file's bytes only to compare, never prints them.

## Open Questions

None for the owner. The one watch item: any new live-state source (another variable family, another dotfile under HOME) needs a line in the scrub; the controls above fail when the scrub is bypassed, not when a new source appears.

## Success Criteria

- Run with the Mac's real state in the environment, both toys print their OK line and the rows pass in a qa lane on the Mac.
- Every assertion that was there is still there; the new controls fail when the scrub is removed.
- The diff is the two toys and this goal's records; the docs check passes and the private scan is clean.

## Distribution Plan
