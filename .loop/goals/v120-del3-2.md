## PR notes

### The one behaviour change, and the risk the owner decides (plain words)

Messages relayed between sessions no longer count as the owner's words (DEL-3.4, ruling TD706). Before, `layers.relay` counted words relayed from the top session except in safety classes; now a relay from `top` or a `peer` is refused, and only a record the operation session wrote with a verified stamp counts. The operation session checks that the owner's own turn holding the same words exists in the session where they were typed, and writes `verified: SESSION@TIME#HASH8` (the hash of the exact words) into the record. Scripts never read raw transcript files. Each heartbeat the operation session re-checks every stamped record from the last 24 hours with `worker.py owner-words-check ID`; a mismatch, or a session or turn that cannot be found, revokes the record, opens one issue (no words in it), logs it, and the check-in shows it.

Remaining risk, stated plainly: a forged record that carries a forged stamp passes every reader until the next heartbeat re-check finds it. This pull request changes the owner-words guard, so it waits for the owner's word even when green (DEL-3.1 item 1). It fixes #5733.

### Known gaps (rulings TD712)
- DOC-2 delegated records (`--from top --delegated`) are exempt and match as before; the owner's 23:28 guardrail ended that delegation for reviewed text, so the path should be retired in v2.0's consolidation on the owner's word.
- A mailed reply is refused loudly once stamps are on; the owner types the answer in any operation session. The owner's mail is never read to verify.
- Owner words stay local to each machine; nothing is exported to origin because the repository is public. DEL-3.4's test runs on one machine. Sharing the record across machines over a private channel is a known gap.
- The keyword matchers for list items 2 to 5 are narrow on purpose (the existing checks' questions stay answered), so those items rest mainly on the kind a worker reports. A question with no kind and no matching words goes ahead.
- A finding title with safety words in it still reaches the owner: `mailbox.py finding` refuses it without the owner's words.
- Stamps are attestations, not proof; an action taken on a revoked record is listed in the check-in, not undone.

### Changed by design, not loosened
dev/toy/test-three-level.py (a top relay is now refused, a delegated record counts), dev/toy/test-full-auto-all.py (an ETA choice takes the recommended path; one safety-class case and one waits case are swapped for equal-count ones so the counts 25 and 5 that row full-auto-safety-waits asserts hold), dev/toy/test-hard-eta.py (an ETA change never skips review or qa). Every assertion still checks at least what it checked before.
