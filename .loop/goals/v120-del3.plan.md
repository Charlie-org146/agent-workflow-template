### Design

1. **The list (DEL-3.1).** New file `.loop/owner-decisions.md`: five numbered items exactly as the page words them (safety classes, what the features promise, freezing a release's brief, shipping a major or merging a major template update into another repo, posting outside the owner's repos). It is data, not a script, so it needs no package slot. A small reader in auto.py returns the matching item or "". The safety-class item reuses the existing CLASSES patterns (one source: they move into the list file as data); the other four items match by the `kind` the worker reports (new kinds: promise, brief, major, external) plus keyword patterns in the file. Only the owner's words change the file: a check refuses any change to it in a pull request without an owner-words record naming `owner-decisions` (same shape as the DOC-2 LOCKED check).
2. **Everything else takes the recommendation (DEL-3.2).** `why_not` is rewritten so that, with `full_auto` on, a decision waits only when `on_list` matches or there is no recommended answer. ETA choices and always-ask goals keep waiting (never loosen a check). `decide_all` answers within the pass; the operation round already runs it each cycle, so the 2 minute bound is the round interval (checked in the toy with a fake clock). The log line gains the options, the reason and an undo line: `undo: <exact words>`; the undo is the worker command that restores the other option, built from the waiting record's `words`.
3. **Bugs fixed without asking (DEL-3.3).** A lane that finds a tool bug calls the existing finding path; the path files one issue (dedup by title) and queues one patch goal (`goal.py queue`, kind patch) that merges on green. A fix whose only form changes a promise or loosens a test is marked `promise` and goes to the list. The kind is decided by the finding's `--kind` word, never inferred from the diff.
4. **Words count wherever typed (DEL-3.4).** Today owner-words.tsv is one file per git common dir (auto.py:183-187), so words typed in an operation session on another machine are not in this machine's file; machines already share small JSON blobs through refs on origin (machines.py:9-12: refs/loop/handover, pr-turn, snapshot, and the mail ledger in mailbox.py). The plan adds one such ref, `refs/loop/owner-words`, written by `sessions.py owner-words --from owner` (sessions.py:242-259) in an operation session (never a worker: sessions.py:245-246 already refuses) with the session name the record was typed in (the `who` column, auto.py:197), and read by `owner_rows` (auto.py:202) as local rows plus ref rows. Only `--from owner` rows go to the ref. `--from top` rows (relayed, counted today except for safety classes: layers.relay, layers.py:306-316, pinned by the "relay counts except safety" row in layers.defaults, layers.py:321) stay local and are never exported, and `--from peer` stays refused. So a message relayed between sessions still never counts as owner words on the shared path, and no existing relay rule is loosened or tightened. A reader that finds the ref unreachable falls back to the local file (fail closed: fewer words, never more).
5. **Decided for you (DEL-3.5).** The check-in already lists what was decided since a stamp (`auto.since`, auto.py:152; checkin.py:137-138). The board gets a "Decided for you" block from the same call, each AUTO line with reason and undo words. One undo line typed by the owner (`undo N`) is recorded as owner words and reverses that decision (sends the opposite option to the worker, marks the line undone). Rendered by a function in board.py; board_status.py is not touched (at cap).
