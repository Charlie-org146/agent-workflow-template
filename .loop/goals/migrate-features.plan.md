# migrate-features: plan

## Implementation plan

Goal: the 27 live requirements on the frozen base (origin/main at 48ac06e7d, which does not yet hold DOC-27 and DOC-28) become features in place (ID, page and every word kept), every Reviewed mark cleared and reported, missing metrics, tests and references marked, features over five lines listed `to split`, and a re-run that leaves an empty diff. The five done lines are in the goal file and are cited by number below. Spec for the shape: DOC-27 on the owner's pinned draft page, used as a spec only; no requirement text is added or changed. Design: `.loop/goals/migrate-features.design.md`.

Files (inside the frozen touches docs/wiki, README.md and docs; goal files and the goal's own `.loop` records are exempt):
- `docs/migrations/features-v1.py` (new; standard library plus the repo's own `criteria.py`, `pageformat.py` and `prd.py`, imported by path from `skills/workflow-docs/scripts` relative to the repo root; under 19,000 bytes, the repo's cap for a script; if it runs over, `check` moves to `docs/migrations/features-v1-check.py` because the cap is per script, and no assertion or report column is cut): `run [--base REF] [--skip IDS]` and `check [--base REF] [--skip IDS]`; arguments are validated (a ref pattern; IDs as `^[A-Z]+-\d+$`) and passed to subprocesses as lists, never through a shell. `--skip` defaults to DOC-27,DOC-28, the entries doc27-28-text adds in the new format; they are left byte-for-byte alone, named in the report, and may be absent on the old base. Both default to base `git merge-base HEAD origin/main` and need `--base` offline.
- `docs/migrations/features-v1-report.md` (new, written by `run`).
- The 11 feature pages under `docs/wiki` that hold requirements: entry lines lose their Reviewed mark; each entry gains one marker block.
- No change to README.md, Home, Principles, Tests, Roadmap, How-to-use pages, figures, any script under `skills/`, any test, `regression.tsv` or `.loop/config.json`.

Steps:
0. Precondition for the final `run` and `check` (not for building): doc27-28-text has merged and main is merged into the branch; stop and report to Operation if DOC-27 or DOC-28 arrives Reviewed. If the merge conflicts in a page, take main's page and run `run` again; the script derives everything from the page, so nothing is merged by hand. `check` then also proves DOC-27 and DOC-28 are present and byte-equal to main; they arrive Unreviewed from that goal, which done line 4's zero-Reviewed proof requires.
1. Read data with the repo's own parsers, so the script never re-implements them: entries and their text from `criteria.blocks`/`LINE`/`subs` and `pageformat.unit` (the string the Revisions rows, the seals and the README tables use; `subs` stops at the first blank line, so a marker block is never read as lines or as text, on a first run or a re-run); linked tests from `criteria.test_rows`; Follows cells from the Principles table via `pageformat.cells` (an ID missing from the table, present twice, or with an empty or dash cell is `reference missing` and is listed in the report; a cell is sanitised before it is written, with no `|`, newline, `<!--` or `-->`); Success metric bullets from each page's `## Success metrics` (an ID matches only as an exact token, not preceded or followed by a letter, digit or hyphen, so DOC-2 never matches DOC-27 or DOC-2-x; two matching bullets read `Success metric 2, 5`, positions counted from 1); old Reviewed marks from the page lines and `git show BASE:page` (date, seal) and, when the shared reviews log exists (`$(git rev-parse --git-common-dir)/loop/reviews.tsv`), the latest `review` row per ID (time, record text), else the report says `record not available`; a Reviewed mark counts as an old mark only if its line is present byte for byte on BASE's page; the review-log row is context, not proof of that mark, is labelled so in the report, is sanitised and cut to a fixed length before it is written, and is left out of every comparison and of the empty-diff proof.
2. Per entry compute: text hash before (sha256 of `unit`, which normalises whitespace, so step 5 also proves the pages byte for byte); its lines, which are its sub-bullets (every entry has at least one because the page check requires it; the script refuses an entry with none; the entry line is not counted); per line `metric` (`Success metric N of this page`, else `metric missing`) and `test` (`N linked rows, see Tests`, else `test missing`; tests link by ID, so every line of an ID shows the same count); the feature's reference (the Follows cell verbatim, else `reference missing`); and `to split` when it has more than five lines. The marker block is only `  - ` bullets, because the page check flags any other indented line (an indented comment line was tried and fails): one blank line, then `  - Feature markers v1`, `  - Reference: <value>` and one `  - Line k: metric <value>; test <value>` per sub-bullet.
3. Write: on the entry line replace `**Reviewed DATE**` by `**Unreviewed**` and drop `<!-- reviewed HASH -->`; on a page whose own `Review:` line is Reviewed (Automation, Regression, Setup) write `Review: **Unreviewed**` through the repo's own `prd.unreview_text`, dropping its `<!-- prd ... -->` lock because that lock covers the requirement lines; after the entry's last sub-bullet insert the marker block, replacing an existing one (from its `  - Feature markers v1` bullet through its last `  - Line` bullet), never adding a second. Everything is built in memory first: all 11 pages are built and every text hash is compared before any file is written; a mismatch writes nothing. Files are then written to temporary names and renamed, the report last. `run` never commits; if it fails after the first rename it prints REFUSED, the list of files it touched, a `git checkout --` for those paths (safe because the targets were clean) and the deletion of the report if it is new. Pages are read and written with `newline=''` so no other byte moves. `run` refuses (exit non-zero, writes nothing) when a page holds a Reviewed mark whose line is not byte-identical on BASE's page, so it never clears a review the owner made after BASE; marks BASE holds (main's pages after the merge in step 0) are cleared again and the report's cleared-marks table is carried forward. `run` also refuses when any path it would write has uncommitted changes, and names its temporary files as dotfiles outside docs/wiki, removed in a `finally`. Line endings are detected per page and the inserted lines use the page's own; the last entry of a page with no final newline still gets exactly one blank line and the block; a re-run removes a block only from its header bullet through the following `  - Reference:` and `  - Line k: metric ...; test ...` bullets, never a real sub-bullet that starts with Line.
4. Report (`features-v1-report.md`): a table of the 27 IDs with page, hash before, hash after, lines, metric, test and reference results; a table of the old marks cleared (the 26 requirement marks with ID, date, seal and record, and the 3 page-level marks with page, date and lock; SET-10 was already Unreviewed, so 26 of the 27 entries carry a cleared mark and the report lists 29); the `to split` list with line counts (five is DOC-27's cap on requirements per feature; the owner consumes the list when reviewing); the skipped IDs; totals labelled `requirement marks cleared 26`, `page-level marks cleared 3`, features to split, and, per line and per ID, `metric missing`, `test missing` and `reference missing`. The counts 27, 26, 3 and 29 are derived from the parse and asserted against BASE, so a new old-format requirement fails with a named error instead of being miscounted; the record column of the old-marks table is context only. The report holds no time or date of its own run, so a re-run writes the same bytes; on a re-run only the cleared-marks table and its two totals are kept from the existing report, and everything else is recomputed.
5. `check` writes nothing to the tracked tree (it unpacks the committed HEAD with `git archive` into a temporary directory removed in a `finally`, registers no git worktree, and fails with a named error if tracked files are dirty) and shares no code with `run` beyond the repo's parsers. It proves, against BASE (the `check` base: `git merge-base HEAD origin/main`, the main tip last merged into the branch, so a later commit on main never fails done line 2; `check` warns when origin/main has moved past it and asserts the 27 non-skipped IDs are present on it with the text hashes the report lists): done line 1, hash equality per ID, the 27 report rows, the inventory (the 27 IDs, their pages and text hashes) equal to the frozen source `48ac06e7d`, and DOC-27 and DOC-28 byte-equal to BASE; done line 2, an independent byte proof for each of the 11 pages (strip the marker blocks, restore the three mark forms from the report, which are the entry mark with its `<!-- reviewed HASH -->` and the page `Review:` line with its `<!-- prd ... -->` lock, and the page must equal BASE's page byte for byte, which also pins every ID to its page), and every changed file is one of the 11 pages, the report, the script, `.loop/goals/migrate-features.*`, `.loop/kept/migrate-features.tsv` or a path the lane or `goal.py pr` regenerated, each named in the check output after a rehearsal (a Tests table re-render, `.loop/START.md`) and each shown to hold no Reviewed mark and no requirement text change, and every other file is byte-equal; done line 3, each ID's Revisions rows byte-equal, equal counts of linked tests and Follows references, and every line carrying a metric and a test result and every feature a reference result; done line 4, zero Reviewed marks outside the report (found by the entry-line and `Review:`-line patterns, not by a substring), and the (ID, date, seal) and (page, date, lock) rows recomputed from `git show BASE:page` equal to the report's 29; the goal file's `## PR notes` holds the exact sentence `release gate (review.py check_reviews) now lists every Unreviewed requirement, the 27 migrated and DOC-27 and DOC-28, as not Reviewed`; done line 5, `run` twice on the scratch copy leaves an empty diff and gives the same line counts as the first parse; `check` runs again on the head that `goal.py pr` pushes (it merges main and regenerates documents first) and that head's SHA is reported.
6. Gates run on the full migrated tree right after `run`, before `check`, and again after the merge in step 0: `docs.py check`, `criteria.py render --check`, `wiki.py prepare` (its output is committed only if every file it writes is inside step 5's list, else stop and report), `health.py check` (run on a `git archive` copy of BASE and of HEAD in one window, FAIL lines compared as sets; the difference must be exactly six lines matching `principle \d has no Reviewed requirement`, the `principle-map` rule's expected effect of clearing every mark; main is red on defect-test rows today; Operation is told before merge because other lanes will see health red) and the private-name scan that `goal.py pr` runs. If any gate rejects the marker block or the `docs/migrations` location, stop and report to Operation; the placement is not changed silently. The block's placement is a tested hypothesis until these gates pass on all 27 (tried on DOC-26 alone: DOCS OK and TABLES OK; the build's first step repeats it on all 27 entries with a throwaway insertion, before the report and `check` are written).
7. Write the sentence of step 5 and the rest of `## PR notes` first (what changed, the report, decisions D1 to D5 as taken, the deferred toy test and regression row, which need `dev/toy` outside the frozen touches and stay in the PR notes as the accepted record for Operation to file or not, the pinned DOC-27 spec path `.claude/worktrees/consolidate-documentation-9216aa/operation-top/readme-drafts/frozen-source-v1.1.0-2321.html` with its sha256 prefix a8206e3dd931595e (DOC-27, merged by doc27-28-text, is the durable copy; cite its page), that the marker blocks are write-once snapshots refreshed by re-running `run` until T3's checker recomputes them, that health on this repo shows those six principle-map FAIL rows after the merge until the owner reviews one feature per principle (reported, not fixed: `rules.py` is outside the frozen touches), that this is an internal cleanup of this repo and adopting repos migrate in a later goal, why the 29 marks are cleared (the owner's o700 order; DOC-27 lets a feature be Reviewed only by the owner's typed words naming that ID, and the old marks came from relayed answers), that the marker bullets are indented bullets that a checker counting bullets without stopping at a blank line would count (T3's input), a request that Operation hold wiki edits from other goals until this lands, the outputs of the manual negative-control runs (a forced hash mismatch, a new Reviewed mark, one broken proof, a CRLF page, a last entry with no final newline, a sub-bullet starting with Line, an ID-token collision, a hostile Follows cell, an absent reviews log, and `run` interrupted between renames with the recovery exercised on a scratch copy), and that the branch was merged up to main after doc27-28-text merged); commit the migration (pages, report and these notes) in one commit; run step 6's gates, then `check`; append the `check` output to the PR notes and commit again (goal files are exempt from `check`'s list), then run `check` once more on the final HEAD and quote that run; before `goal.py pr` assert that `.loop/config.json` on the merged tree has auto_merge false and stop and report if not; fill `## Verify by hand` in the goal file; commit; stop at `goal.py pr`. The `autoMergeRequest` result exists only after the PR is opened, so it is reported to Operation, not written in the PR notes.

Not in scope: DOC-27 itself (another goal), any page rebuild, How-to-use removal, figure removal, the second repo, splitting any feature, any checker change (T3), a regression row or toy test.

Verification: step 5's `check` output is in the PR notes; qa runs the affected regression rows only through the lane and never runs dev/toy/test-machine-log.py or dev/toy/test-platform-limits.py. Order and safety: the branch is brought up to main only after doc27-28-text has merged, which also gives it auto_merge false; `merge.py` is never run, auto-merge is never armed and a printed NEXT line that merges is not followed; right after `goal.py pr` run `gh pr ready --undo <n>` (the PR stays a draft until the owner says) and `gh pr view <n> --json isDraft,autoMergeRequest` must show true and null.
