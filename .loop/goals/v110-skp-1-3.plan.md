## What it does

A new script cover.py (delivery skill, imports only delivery siblings, lazily, clean --help, about 13,700 bytes of a 17,500 budget) decides per ROW. Covered rows = the rows the lane planner (lanes_cli affected) selects for the diff, minus rows in .loop/regression-skips.tsv (GitHub's Ubuntu runner skips them), minus completion.off_pr rows (.loop/regression-limits.tsv), minus the previous lane's failure and flaky ids. Local rows = every other selected row. All of these predicates must hold, or NOTHING is covered and the whole lane runs as today: (a) a GitHub origin, base is main; (b) origin/<base>:.github/workflows/regression-pr.yml has the pinned meaning (--tier goal, nightly --reuse, the matrix cell count, the cutgate aggregate line, the final `test "${{ needs.shard.result }}" = success`, numeric tolerance, no pull_request filter or job-skipping if, AND the `merge_group` trigger and the `small` job that the merge queue's own run needs) read with git show, never the working tree; (c) regression_runs is actions; (d) `git diff --name-only origin/<base>...HEAD` has a non-doc path (the workflow's .md and .loop goals/kept filter) and nothing under .github/workflows; (e) the base ruleset lists `affected` as a required check (private.required_checks) AND the job that provides `affected` is in the pinned regression-pr.yml (today the contexts are unbound, so the claim is "the rule names the context and regression-pr defines the job", and step 0 decides whether that is enough); (f) the repo is public; (g) a fresh `git fetch origin <base>` succeeded. The cover is a ONE-WAY ratchet: claimed at qa or ship, only confirmed or dropped at pr, never newly granted at pr.

The gate is GitHub's, not ours (TD1698): goal.py pr OPENS the PR and the merge queue's required `affected` check decides whether it merges. No worker waits for the run, no state records a wait, and merge.py does not revalidate the cover; a red run stops the merge in the queue as for any PR, and shows on the board and the check-in.

Flow, per step (hooks are one to three lines each, the logic is in cover.py):
- qa and ship (flow.py:176, before role.lane): cover.skip claims, stores {name, base sha, covered ids} in state["covers"] through fit.run_saver, and prints one line: "COVERED N rows by <name>; running M locally: <ids, capped> (claimed; pending PR recheck and GitHub execution)", or one "COVER OFF: <predicate> <fact>. The local lane runs in full" line per goal and step (silent when predicate (a) or (c) can never hold). The partial lane (lane.py launch, lane.py:169) runs only the local rows through a row-id lane (the ids-lane flag below). The words SKIPPED and NOTRUN are never printed (lane.py and fit.py parse them); a toy asserts no cover line matches those regexes. The qa/ship prompt (flow.py LANE constant, flow_steps.py:116) says "N rows are covered by <name>; the M other rows run by flow.py; run no suite yourself", and sizing.block's `full-test-run` line says "covered by <name> (claimed; pending PR recheck and GitHub execution)".
- record qa|ship (goal_steps.py:16, need_lane): cover.need waives the lane requirement only for rows RECOMPUTED at the current HEAD as covered, still requires the partial lane's own `.ok` for the rest (a failed uncovered row is refused, code LANE_MISSING_UNCOVERED naming the rows and `python3 .../cover.py lane <slug> <step>`, which works from a recorded qa and from an active .asked step), and over_caps still runs.
- pr (goal_steps.py cmd_pr): the cover is re-checked once before the pr lane (head-independent facts) and once after role.record's bookkeeping commit (final head); a late loss runs the full lane exactly once, redoes the bookkeeping commit, a red lane goes through fit.pr_fail, the second pass never re-enters the first. A lost cover is a NOTICE (COVER_LOST, non-fatal) that drops the `.ok` and `.last` of qa, ship AND pr so a partial pass is never reused. The PR text (role.lane_part replaced by cover.pr_part) lists "Covered by the PR's reached-test run (regression-pr): N rows" and "Run locally: M rows (ids)", plus the local minutes this goal's own lanes took (measured) and the minutes the same lanes would have taken without cover (an ESTIMATE from the recorded row times, labelled as an estimate, since a covered goal never runs the full lane) (D5, reported not required) and "estimated avoided: ~X min (covered rows' recorded times) or unavailable". After pr_open the body refresh uses a persisted body_refresh checkpoint {PR number, head, part}, `gh pr edit`, a BODY_STALE refusal on failure (the PR is open and its body stale; `goal.py pr <slug>` only retries the edit, with no merge, lane or push), through the refusal contract (REFUSED ... Fix ... (CODE), NEXT). No private status is posted for a covered goal. The step then ends as today (step=release).
- merge (merge.py): ONE new refusal, COVER_NOBATCH, at the batch entry before pods.merge_lock (merge.py:175; a single slug with --batch goes down that branch too), naming the covered slugs and "merge it alone: merge.py <slug>". ## Safety classes (one plain sentence each)

Certificate drop (destructive): when a cover is lost the goal deletes its own earlier qa, ship and pr lane pass records so a partial pass is never reused, and it deletes nothing else. Ruleset reliance (security): the cover is granted only when the base ruleset lists `affected` as a required check and regression-pr defines that job, read (not probed) at build step 0, and the goal trusts GitHub's merge queue to stop a red PR run from merging. Private-repo rule (private data): a private repository never gets a cover, so its local status posting and full lane stay exactly as today.

## Limits and residual risks (stated)

The fake gh does not prove GitHub's enforcement; step 0 is the one real-GitHub check and it only reads. Selection equivalence between lanes_cli affected (local) and tiers.plan (the workflow) rests on a toy and on the PR text listing the covered ids; an independent manifest checked by cutgate is a named follow-up with the residual risk that a future planner divergence leaves a row marked covered and unrun until the nightly. The workflow pin protects the workflow file, not the planner, runner or cutgate code a PR itself changes. The merge queue, not this goal, stops a red run; a cover lost after the PR opened is not revalidated at merge (TD1698). SKP-1.2 (regenerate once) and SKP-1.3 (time limits), the CBS-1 sizing table and the How-to page are out of scope.
