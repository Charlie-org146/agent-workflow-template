## What it does

A new script cover.py (delivery skill, imports only delivery siblings, lazily, clean --help, about 13,700 bytes of a 17,500 budget) decides per ROW. Local obligations come from tiers.plan, the planner the local lane really uses (it selects prior FAIL, SKIPPED and flaky rows independently of the diff's reach, tiers.py:204-219, which lanes_cli affected does not read), and proven CI coverage is subtracted: Covered rows = the rows BOTH the lane planner (lanes_cli affected) and tiers.plan select for the diff, minus rows in .loop/regression-skips.tsv (GitHub's Ubuntu runner skips them), minus completion.off_pr rows (.loop/regression-limits.tsv), minus the previous lane's failure, skipped and flaky ids, minus every row whose level is L0 once the table has levels. Local rows = every other selected row. (tiers.plan is the planner regression.cmd_run itself uses, regression.py:285, for the local lane AND for CI's `run nightly --reuse --tier goal`; lanes_cli affected is merge.py's approximation of reach; covered requires BOTH.) All of these predicates must hold, or NOTHING is covered and the whole lane runs as today: (a) a GitHub origin, base is main; (b) origin/<base>:.github/workflows/regression-pr.yml has the pinned meaning (--tier goal, nightly --reuse, the matrix cell count, the cutgate aggregate line, the final `test "${{ needs.shard.result }}" = success`, numeric tolerance, no pull_request filter and the `on:` has `merge_group` with exactly `types: [checks_requested]` and nothing else, and ONLY these `if:` forms, verified in the workflow's own lines: job `shard` `github.event_name != 'merge_group'`, job `affected` `always() && github.event_name != 'merge_group'`, the steps `always()` and `always() && needs.shard.result == 'success'`, and job `small` `github.event_name == 'merge_group'` (the queue's one quick job, which stays); any other `if:` on those jobs or steps turns the cover off) read with git show, never the working tree; (c) regression_runs is actions; (d) `git diff --name-only origin/<base>...HEAD` has a non-doc path (the workflow's .md and .loop goals/kept filter); (e) the base ruleset lists `affected` as a required check (private.required_checks) AND the job that provides `affected` is in the pinned regression-pr.yml; cover.py reads the `integration_id` of `affected` and `small` from the rules and requires it to equal the GitHub Actions app id, a named constant checked on every claim and every confirmation; (f) the repo is public; (g) a fresh `git fetch origin <base>` succeeded; (h) the TOOLING-COVER line: the diff touches nothing under skills/workflow-regression/scripts (the regression scripts, including the code that picks reached rows), else the L1 rows also run locally, and every cached result or plan made by the old tooling is invalid (fix 5: row_reach.py joins lanes.py runner()'s hashed tuple, so a change to it invalidates records and cached plans). The cover is a ONE-WAY ratchet: claimed at qa or ship, only confirmed or dropped at pr, never newly granted at pr.

## Safety classes (one plain sentence each)

Certificate drop (destructive): when a cover is lost the goal deletes its own earlier qa, ship and pr lane pass records so a partial pass is never reused, and it deletes nothing else. Ruleset reliance (security): the cover is granted only when the base ruleset lists `affected` as a required check and regression-pr defines that job, read (not probed) at build step 0, and the goal trusts GitHub to stop a PR with a red L1 run from merging (the queue itself runs no test row). Private-repo rule (private data): a private repository never gets a cover, so its local status posting and full lane stay exactly as today.
