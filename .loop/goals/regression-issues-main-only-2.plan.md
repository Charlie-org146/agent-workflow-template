## What could break
- A repo whose default branch is read differently (a renamed default): the runtime read handles it. A token without read access to the repo API: the read fails, no `--live`, a dry run: fails closed, the nightly would stop filing until fixed (the `DRY RUN` line says why).
- The existing toy check that looks for the literal `--live` after `python3 -`: updated in step 4.
- actions.py byte size: step 1.

## Out of scope
The `summary` job (it has `issues: write` but only writes a run summary with an empty token); `regression.py run` locally; any other workflow.

## Fix for the second gate's break (principle 5): the taskkill branch stays
The `except AttributeError: taskkill` branch in run() is what lets the toys run this block on Windows (os.killpg does not exist there; test-portable.sh:7 says so), so it is NOT cut. The byte cuts come from other text only: the timeout `ps` diagnostic (about 330 bytes) and shorter REFUSED/NOTE wording, each first checked with grep -rn over dev/toy and .loop/regression.tsv so no assertion on the cut text breaks; if a cut text is asserted, a different cut is used. Every edit is followed by a measurement in LF bytes against main's 18,980; the build stops and asks operation-pc if the budget cannot be met without touching asserted text.

Also stated, not fixed here (follow-ups, out of scope for a one-line patch): a dry run on a branch still counts `filed` and prints "CLEANUP closed N issues" for writes that did not happen, and in cleanup mode it still sleeps REGRESSION_PACE per would-be write; neither writes anything. The toy fails rather than skips when bash is missing, a deliberate departure from the skip convention (a row must not read as enforced where it never ran). The first nightly after the merge proves the schedule run's real GITHUB_REF and token read; until then it is unproven (and if the default-branch read fails, nightly filing pauses with one DRY RUN line).
