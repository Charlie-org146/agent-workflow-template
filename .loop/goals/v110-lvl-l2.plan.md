### Design
1. **L2 is only the schedule's default target (TD1798; RT-C1).** The setting `ci_levels`, settings.py, survey.py, autorelease.py and lanes_cli.py are NOT touched, and `L2` is not a `ci_levels` value. The generator renders the shard step's target as `REGRESSION_TARGET: ${{ inputs.target || 'L2' }}` when `ci_levels` is `nightly` (the default and this repo's value) and as today's `${{ inputs.target }}` when it is `land`, so `ci_levels: land` keeps meaning the scheduled run takes `REGRESSION_LEVELS` land (the existing test-ci-target.sh `levels` case and milestone.py:332 stay true). So on a nightly repo the schedule and an empty by-hand input run L2, while an explicit `inputs.target` (`land`, `nightly`, a row id or `L2`) is honoured as before. `land`, `nightly` and row ids keep today's behaviour byte for byte, so test-regression.sh lines 201-202 and the existing rows stay. EFFECT on adopters, named in the PR body and the owner question: a repo that regenerates its workflow and has `ci_levels: nightly` now schedules L2, whose set is the same rows as nightly but whose red-on-skip rule is new. The L2 set is every row except drafts and covered rows, by the old words (the runner does not read levels.py or stages; the table's old column stays until G4). The SUITE_TIME condition becomes `TARGET in ("nightly", "L2")`. An unknown target exits 1 with `L2_BAD_TARGET <value> (quoted, cut to 40 characters, control characters stripped): the targets are L2, land, nightly or a row id. Fix: gh workflow run regression.yml -f target=L2`; a valid target that selects zero rows exits 1 with `L2_NO_ROWS`. The dispatch input description gains the word L2. A toy greps the generated file for any `${{ inputs` inside a `run:` body and runs a hostile value (quotes, `$(...)`, newline). The summary job gets `REGRESSION_TARGET` and the ref as env (item 3).
2. **States stay; EXEMPT is a comment list.** The result schema is unchanged (STATES stay PASS, FAIL, SKIPPED, KNOWN; `id TAB state`). Per row, only when TARGET is L2: PASS; KNOWN (known list, checked BEFORE skipped, so a known row that exits 77 or runs out of time is KNOWN and counts as run, as the page says); a row on `.loop/regression-skips.tsv` WITH its reason that exits 77 (the by-design skip: TOY_SKIP_FILE) or is not started for job time is written `id TAB SKIPPED` plus the comment line `# exempt <id> <reason>` (o993: counts as run, neither red nor incomplete, shown apart); an exempt row that FAILS TO START (exit 126 or 127, a missing tool or interpreter) is FAIL and red, not exempt: o993 covers a skip by design, a start failure is a defect (A4; named in the PR body); any other skipped row is written `id TAB SKIPPED` plus `# skipped <id> <cause>` where cause is `out of job time` or `cannot run here`; FAIL. A skipped row prints a distinct line `SKIPPED <id>: <reason>`, not a failure-shaped line (TD1787). Comment lines are ignored by the existing parser, so no consumer of the results file changes. For land, nightly and row-id targets the state order, the printing, the exit rule and the issue branches are today's code, unchanged (F8).
3. **The verdict is computed only inside `cmd_summary` (TD1793 b; RT-C3).** The summary job passes `REGRESSION_RESULT: ${{ needs.regression.result }}`, `REGRESSION_TARGET` and the ref as env. `tests.py summary` reads the `#` comment lines of the combined results file in the same pass and, ONLY when the target is `L2`, prints first the tally `L2 <RED|INCOMPLETE|GREEN>: ran n, known n, exempt n, skipped n, failed n` and, only on main, ONE line `L2_VERDICT <sha> red|incomplete|green`, kept as the artifact `l2-verdict` (30 days). On any other ref (a branch dispatch: the shards' gh writes are would-only there) the tally prints but there is NO `L2_VERDICT` line, no artifact and no issue, so a branch run can never publish a verdict (A7). Land, nightly and row-id runs keep today's summary line, so a one-row run never reads `L2 GREEN`. **Verdict table, RED > INCOMPLETE > GREEN:** RED if any result line is FAIL or any non-exempt SKIPPED row is recorded (a job-time skip is red; skip-only is red); else INCOMPLETE if `needs.regression.result` is not `success` with no recorded red row (a shard that died, timed out, was cancelled or reported nothing), or fewer shard result files arrived than `SHARDS`, or any `# gh-failed <operation> <row or label>` line is present (an issue or label write failed, or its outcome is unknown); else GREEN. Because the matrix result is an input, a failed or cancelled shard can never print GREEN. Exempt and known rows count as neither. No `L2_VERDICT` line for a sha means incomplete. When EVERY shard exits with the same `L2_BAD_TARGET`, the summary prints that code as its first line instead of per-shard noise. Covered rows: `L2_COVERED <id> -> <worst state> via <cover id>`, reading the covers from G1's record file (the build reads its real name and columns from G1's merged plan; until that file exists on the base, a covered row prints `unresolved` and does not make the verdict incomplete; once it exists, a missing cover is incomplete); known or exempt covers are named; a covered row files no issue. Layout: verdict and tally first, then failed rows, skipped, missing, then covered and exempt lines. **The exit code survives (RT-C2):** the summary step becomes `rc=0; GH_TOKEN= python3 tests.py summary ... > "$out" || rc=$?; cat "$out" | tee -a "$GITHUB_STEP_SUMMARY"; exit $rc` (the fallback printing stays but no longer swallows the code), with `continue-on-error` removed from that step, so RED and INCOMPLETE fail the job; a toy runs the generated step text.
4. **One issue for every skipped row (TD1793 c), filed by a tiny separate step.** A new step in the summary job, BEFORE the summary step and with the token, runs `python3 tests.py skipped-issue --results <combined file>` (a small subcommand in the same embedded tests.py; main only). It files or updates ONE issue `Regression: L2 skipped rows (n)`, marker `<!-- loop-l2-skipped -->`, label regression, whose body lists EVERY skipped (not exempt) row id with its cause and a fix line per cause: for time skips, the matrix size `SHARDS` in actions.py and `regression.py workflow` (raise SHARDS only if the bytes allow); for cannot-run-here, the row's own prerequisite, or put it on `.loop/regression-skips.tsv` with its reason, which the owner approves. The body is edited in place only when the set of ids changes; no comment is added while the same rows stay skipped (F7). It closes only when a full L2 run has zero non-exempt skipped rows. No per-row skip issue, no roll-up, no rotation. The `gh` calls have a 60-second timeout each and a 3-minute step budget; a failed or unknown write appends `# gh-failed <operation> skipped-issue` to the combined file (the summary step then reads it) and an unknown write is looked up once before one retry. Done line 2 is met literally: one issue names each skipped row.
5. **Failing rows and issue transitions (L2 only).** A FAIL row keeps its per-row issue from the shard (existing code), plus the label `l2-red` (`gh label create --force`, so 16 shards racing do not fail; a label failure prints a `FILED ... FAILED` line and records `# gh-failed`). The issue body says only "Labelled l2-red." **B4, named: nothing in the repo reads `l2-red` today** (only release.yml mentions main-red), so the body makes no claim about a reader. TWO CHOICES FOR THE OWNER: (A) the main-red goal (and its plan) is made to read `l2-red`, a change to a goal outside this one; or (B) done line 3's wording "the main-red goal names it" is replaced by a ruling that the label l2-red is what names it. `main-red` is not used, so release.yml's hold is unchanged. Transitions: a skipped row that later FAILs is listed in the skipped issue until its failure issue exists, then leaves it; a pass closes the failure issue "Passing again." (no label-removal call exists, none is added: the closed issue is the transition); the cleanup mode (code 125) is excluded from every count and files nothing; for TARGET L2 it no longer closes the current skipped issue (it closes only issues of rows removed from the table), while for land and nightly the old behaviour is unchanged (F8); a toy proves skip, cleanup, skip keeps the one issue. Issues written by the old code are left alone. `shown()` is given the first execution's captured output (a fixture counts invocations and fails if a failed row runs twice); issue bodies are redacted for known token shapes and cut to the last 20 lines.
