### Design (one list; every accepted gate change d3 to d23 and the later ones is absorbed here)
1. **One target word, old words unchanged.** The scheduled workflow and the by-hand full run use target `L2` (set explicitly in the generated file: REGRESSION_TARGET and the schedule's env both `L2`). `land`, `nightly` and a row id keep today's behaviour byte for byte, so the old toy assertions at test-regression.sh:201-202 stay and keep passing for those targets; the new rules apply only to `L2` (operation ruling, C5). The set for L2 is every row except drafts and covered rows, by the old words (the runner does not read levels.py or stages: C2; the table's old column stays until G4). The SUITE_TIME condition becomes `TARGET in ("nightly", "L2")`. The target is normalised once; an unknown value exits 1 with `L2_BAD_TARGET <value> (quoted, cut to 40 characters, control characters stripped): the targets are L2, land, nightly or a row id. Fix: gh workflow run regression.yml -f target=L2`; a valid target that selects zero rows exits 1 with `L2_NO_ROWS`; stderr carries both. The existing `inputs.target` is passed as an env var already; a toy greps the generated file for any `${{ inputs` interpolation inside a `run:` body and runs a hostile value (quotes, `$(...)`, newline).
2. **States and the one verdict.** Per row: PASS; KNOWN (known list, checked BEFORE skipped, so a known row that exits 77 or runs out of time is KNOWN and counts as run, as the page says); EXEMPT (a row on `.loop/regression-skips.tsv` WITH its reason, exit 77 or not started: o993, counts as run, printed `L2_EXEMPT <id>: <reason>` and counted apart); SKIPPED (not run, for time `out of job time` or exit 77 `cannot run here`); FAIL. One display word for the owner: "skipped". The final tally always reads `L2 <GREEN|RED|INCOMPLETE>: ran n, known n, exempt n, skipped n, failed n`. A skip-only red run prints, per skipped row, a line in the same shape the autorelease reader already parses for a failure (the build reads that pattern in the autorelease code first and uses it), so the red is not "unknown".
3. **One aggregation point, after the shards.** Every shard writes, before it runs a row, an `# expect <id>` line for each row in its own slice (selection is deterministic), so the expected inventory is persisted. The summary job (not the shards) reads all shard result files and computes: missing rows (expected minus reported, by id, or the shard number when its file is absent or header-only) printed `L2_MISSING <ids>: <fix>` and counted as INCOMPLETE; covered rows (`L2_COVERED <id> -> <worst state> via <cover id>`, worst state of its covers, missing covers fail closed, never green; a covered row files no issue of its own, the cover's issue names it); the tally; and ONE machine-readable line `L2_VERDICT <sha> green|red|incomplete` written to the summary and kept as an artifact. The summary job exits 1 on red or incomplete; a shard that dies or is cancelled already fails its job. The result line schema is `id TAB state` plus an optional third field; `tests.py summary` and every consumer of the results file are updated together and a header-only or older-schema file is treated as missing, never as success. The consumers: the l2-red label, the main-red goal, and G4's release-cut wait read the verdict line.
4. **Skipped is red, with reasons and a bounded count.** A SKIPPED row (not known, not exempt, not a draft) makes the shard exit 1 and gets ONE issue named `Regression: <id> skipped` (existing marker "The row `<id>` was skipped.", label regression) whose body carries the cause, the fix, the run link, the shard and the effective limits. The fix lines are concrete: for `out of job time`, edit `SHARDS` in actions.py and run `regression.py workflow`, and `regression.py times` lists the slowest rows (the build reads the real command names first); for `cannot run here`, the row's own prerequisite, or put it on `.loop/regression-skips.tsv` with its reason, which the owner approves. When more than 10 rows skip for the same cause one roll-up issue replaces the per-row ones, so a bad night files one issue. Time-skipped tail rows are rotated: the order within a shard starts at an offset taken from the run's date (day number), so the same rows are not skipped every run; a toy fails when the same row is skipped in two consecutive fixture runs with enough time for the rest. First landing: without o993's reading the run would be red on day one because of 15 by-design skips; with it those 15 are EXEMPT.
5. **Issue transitions, one marker per row.** skipped to failing: edit the body, add defect (existing code); failing to skipped: comment "now skipped", keep the issue open (a skip never closes a failing row's issue); pass: close "Passing again."; a repeat skip comments at most once per calendar day (the issue's updatedAt is already read); the cleanup mode (code 125) is excluded from every count, files nothing and no longer closes a current actionable skipped issue (it only closes issues whose row is removed from the table), and a toy proves skip, cleanup, skip keeps the one issue. Issues written by the old code (the old skip text) are left as they are and replaced by the new body on the next skip.
6. **A failing row gets the label `l2-red`** (TD1767; created with `gh label create --force`, so 16 shards racing do not fail; a label failure prints a FILED warning and does not hide the failure) and the body line "Labelled l2-red; the main-red goal reads this label." The line states a fact the code can check; nothing claims a goal names it, and the PR body says that nothing opens a main-red goal. `main-red` is NOT used, so release.yml's hold (main-red only) is untouched; the PR body's Behavior changes lists release.yml as a consumer that is unchanged. The runner runs no `git revert`, `reset` or `push` (a toy greps the generated workflow and asserts the permissions block: contents read, issues write, pull-requests read, no delta).
7. **GitHub calls are bounded.** Each `gh` call gets a timeout and an overall reporting budget; each failure prints `L2_GH_<op> <label|issue|row id>: <sanitized cause>. Fix: <repair>` and counts as FILED-FAILED (the run stays red); an unknown outcome of a write (timeout after sending) is looked up again once before a retry; a toy covers a slow `gh`. Row output is not run again on failure: `shown()` is given the first execution's captured output (a fixture counts invocations and fails if a failed row runs twice); issue bodies are redacted for known token shapes and cut to the last 20 lines.
8. **Existing row and toys.** The row whose description says a skipped row files no issue (found by grep, in `.loop/regression.tsv`) gets its description (and command, if the toy file name changes) updated for the L2-only rule through the approved mechanism `dev/toy/approved-row-changes.tsv` (the rows-only-added guard `tasks-rows-only-added` stays; the operation is told, and it is the same mechanism other goals used). dev/toy/test-ci-target.sh gets its BAD_TARGET assertion migrated to the new text and new cases for aliases and zero selection; its no-work and shell-safety checks stay. test-regression.sh's lines 201-202 are NOT edited.
9. **Regenerate and check.** The workflow is regenerated with `regression.py workflow`; the parity toy passes; no Reviewed wiki text is edited (docs/wiki/Regression.md's "draft and covered rows are not run" stays true); the codes `L2_BAD_TARGET`, `L2_NO_ROWS`, `L2_SKIPPED`, `L2_MISSING`, `L2_GH_*` go in skills/loop-files.md's codes table, and a short runbook paragraph says how to dispatch `-f target=L2` and how to read the tally.
10. **Bytes.** The first draft's real size replaces every estimate here. actions.py (18,997 B) will cross 19,000: room comes first from moving `write` (1,213 B) whole into `actions_write.py` (o994: allowed only because actions.py runs out of room; if the measured file still fits, no new file). slots.py (18,982 B) and tests.py (18,817 B) take the aggregation; whichever would cross 19,000 moves a whole function out first; if that cannot make room, the build STOPS and asks the operation (no new file beyond actions_write.py is approved, and no text is trimmed to fit: GRD-20).
