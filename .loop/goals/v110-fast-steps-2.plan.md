## What is built

1. **One list, one file.** `skills/steps.py` holds STEPS (freeze, plan, build, quick checks, tests, merge, after the merge, release), the legacy labels that map onto them, the write-time label check, the step log, the cause list and the Steps summary. It ships in a pack as `shared/steps.py` (SHARED in `dev/package.py` and in `update.py`) and every skill reaches it by name through a small `moved*.py` helper beside its scripts.
2. **One save hook.** `goal.save`, `release.save`, `sessions.save`, the four monitoring savers, `auto.py`, `flow.py` and `merge.py`'s post-merge write all go through `steps.merge`/`steps.transition`/`steps.commit`: the record is locked, merged, its step clock and cause list are kept from the disk copy, and the start/end lines are appended once. Where `fcntl` is missing, lanekit's lock shim is loaded by path.
3. **The step log.** Each step logs start, end, active minutes, tokens and result; a step still running past its limit shows as missed with its cause (fast-clock's `clock.missed`, after the rebase). A done goal with its pull request open waits in `merge`; `after the merge` and `release` are set only inside `finish`; a goal left unreleased ends its merge row. Lines this goal writes say "began", so the board's hold parser does not see them; the board's own numbers are unchanged (a named case).
4. **Causes.** A stop or failure records a structured cause `<step>:<CODE>` in the run record. `steps_page.py file` previews each cause once, grouped with its repeats, with one fix per cause. **Filing ships off in v1.1.0**: nothing is written to GitHub.
5. **Release summary.** The release text's `### Steps` block is refreshed at every stage and again at cut; a release cut by hand carries it in its notes and changelog. On the automatic path the block is taken before the release itself exists, so it shows the steps up to the merge.
6. **Display.** The check-in's session cells and by-goal rows name and number steps from the one list (an open pull request shows as `merge`), count against the list's own length, and say a report's "step ship" as "step tests" in the latest column; the board's task goal lines and handoff show the list name only (an off-list label keeps the goal's last known step). The live board draws its flow line, "next:" line, percent bar (total = the list's length) and depth line from the list, its Issues stall line and a waiting goal's report name the step from the list (`stall_lines` and `depth_of` moved whole into `moved_mon.py`), the board's CHANGE lines print a stored step by the list's name (a label change that is the same step is no change), and the handoff's "Waiting on the owner" asks say a failed goal's report by the list's name. A rendered case with a mutation guards each path. `board_log.py`'s FLOW and STEPS stay as stored keys and budget accounting with no byte room to change; a named case checks their numbers do not move.
7. **The page.** `docs/wiki/Steps.md` is generated by `steps_page.py render` from `steps.py`; `docs.py check` fails when it is stale. The summary job of the generated `regression.yml` carries one added step that previews the causes.

## Build tasks (from the plan gate)

A save waits at most 30 seconds for another writer's lock and then refuses with `LOCK_TIMEOUT`, never an endless wait (`steps.commit`, `steps.update`, `goal.save`); a run record that exists but cannot be read is refused with `RECORD_UNREADABLE` and left as it is, never taken as empty and overwritten, while a missing record starts fresh. `steps_page.py` fails on a repository git cannot find or a record it cannot read and treats a folder with no records as an empty store. `steps.say()` never rewrites a flow-file key or a lane name, which are command arguments. The end and began lines sit before the caller's own new lines, so a stopped entry stays next to the entry that resumes it and the budget's numbers do not change. The merge-queue finish records the release row (`release_ci`), not a second merge. Everything else the gate raised is deferred, listed with its reason in the PR notes (after-cut hardening of the save hook, the cause pipeline's reach into CI, a manual cut's release row, Windows locking, per-cause retry advice).
