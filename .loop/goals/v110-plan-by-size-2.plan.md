## Design
### D1. A provisional size at plan start (done line 1)
Where it lives: `fit.py` (12,773 bytes; sizing.py has about 956 bytes of room under the 20,480 limit, dev/package.py:48, so sizing.py gets only a few lines). fit.py gets `start_row(state, runs, cfg)`, returning "small" or "large" for a goal with no `sized`: "large" when `fit.view(state, runs)["size"]` is missing or has `small` false (as depth_for treats a missing size, fit.py:91-92), or when sizing.classes_of over the goal text, done lines and touches (touches read as guards.touches_of does) names any class or risky path; else "small". It never returns "medium": the real size is set later from the plan by sizing.py size, and a size only goes up (sizing.grow), so this row is a floor. classes_of over prose is looser than the Files/Gates/Classes text sizing.py size reads, so it can only err toward large (build note).
`sizing.depth(state, step)` gets one new branch, taken only when step is "plan", `on()` is true, the goal has no `sized`, no `depth_override` and is not `one_review`: it reads the row from read_table() and returns "full" when the plan-review form has more than one pass, else "condensed". It catches Refusal (an unreadable table or base config) and then returns "" as today. Every other path is unchanged, including guards._record, which also calls depth() (guards.py:75): with a stored size, a `one_review` goal, an override, the review step or sizing off, the result is today's. A `one_review` goal keeps full (fit.depth_for), as this goal itself does.
`prompted` prints, for that branch, the row's forms by name from the table ("plan-review one-round, red-team one-pass-no-rerun"), and says they are provisional: "sizing.py size sets the real row from the plan; write CHECK lines in the forms it prints". When the row is full it keeps today's "never condense; a condensed reply is refused" wording; guards.py's depth-condensed refusal already enforces it (setting = sizing.depth(...)), so guards.py is not changed.

### D2. REVW-5's round rule (done line 2)
commands.md gets a section "## sizing rounds" with REVW-5's text: "A plan gets the reviews its size's row lists, once. A read after a fix covers only what changed, and at most `{reads}` such reads run. After that, only a finding that makes the plan wrong is fixed, and the build's review checks that fix. A finding about wording alone is a build note at any round." Backticks and no other braces; `part()` in `prompted` gets a `reads` keyword for `.format`. `prompted` appends it after the "sizing plan" block, for the plan step, when sizing is on (a repo without checks_by_size gets today's prompt; stated limit). `reads` is `plan_fix_reads` read from the BASE config (sizing.base_cfg(), as role.setting_of does, never the worktree's), accepted only when it is an int, not a bool, from 0 up; anything else gives 2. `plan_fix_reads` is registered as a setting (owner-approved wording REVW-5; operation-mac added the touches): one row in settings.py's TABLE (`("plan_fix_reads", REPO, 2, "The most reads of fixes a plan gets after its reviews, on the changes only; wording findings are build notes.")`, 407 bytes of room in settings.py, 20,073 of 20,480) and the key with its help line in .loop/config.json beside review_depth, value 2. The generated settings surfaces are regenerated and are touches: skills/loop-files.md (`settings.py reference --write`; dev/toy/test-settings.sh:28-29 asserts it equals the TABLE's reference), .loop/START.md (`entry.py write`) and docs/wiki/How-to-use-Setup.md (`render.py blocks`; `docs check` flags it stale otherwise).
